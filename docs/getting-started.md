# PHI 快速上手

[English](getting-started.en.md) · [文档导航](README.md) · [返回首页](../README.md)

先接通一个工具与一个模型，确认请求正常后，再添加其他工具。

## 1. 安装并准备 CLI

从 [PHI Releases](https://github.com/GoatGit/phi/releases/latest) 下载适合系统与架构的安装包。当前 macOS 发布配置要求 13+；Windows 和 Linux 的具体包型见发布 Assets。

PHI 管理和启动 CLI，但模型服务仍由你选择的供应商提供。打开「应用」页，检查目标 CLI 的安装状态；如果尚未安装，可使用该工具支持的安装入口，或按工具官方说明安装。已有 CLI 的用户，先备份其配置目录。

macOS 可以在 PHI 内通过 Ghostty 终端运行 CLI；其他平台的启动方式依平台集成而定。

## 2. 添加一个供应商

在供应商管理中，选择目标工具对应的供应商类型，填写 API 地址、凭据与模型信息。官方订阅登录和普通 API Key 是不同的接入方式，请按该集成支持的方式配置。

- API 地址应使用供应商明确给出的端点；不要随意重复添加 `/v1` 等路径。
- 模型 ID 必须是供应商实际支持的值，展示名称不一定等于调用 ID。
- 不确定时，先使用预设，再核对供应商文档。没有预设的服务可以尝试自定义供应商。

## 3. 为工具选择模型

为目标工具选择供应商与模型。PHI 的配置写入和本地网关是相互关联但不同的操作；需要协议转换、聚合或故障转移时，按界面提示启用对应的本地路由。

首次配置只启用一个工具。不要同时在其他应用中修改同一个工具的配置，避免设置相互覆盖。跨协议转换无法让模型自动获得其本身不支持的工具调用、图片或推理能力。

具体例子：

- [用 Codex 调用 DeepSeek](guides/codex-deepseek-routing-guide-zh.md)
- [用 Codex 调用 Kimi](guides/codex-kimi-routing-guide-zh.md)
- [用 Codex 调用 Claude](guides/codex-claude-routing-guide-zh.md)
- [在 Claude Code 中使用 Codex](guides/claude-codex-routing-guide-zh.md)

## 4. 验证一次请求

启动 CLI，在临时项目中提交一个简单、不含敏感数据的请求。确认工具实际使用了目标模型，再查看 PHI 的会话和用量记录。用量覆盖范围取决于工具集成与请求路径；费用展示是估算，账单以供应商为准。

## 如果没有接通

| 现象 | 先检查什么 |
| --- | --- |
| CLI 无法启动 | 「应用」页是否识别到安装；在外部终端能否直接运行该 CLI |
| 401 / 403 | API Key 或登录状态、供应商权限、模型访问权限 |
| 404 / 模型不存在 | API 地址、模型 ID、所选协议是否与供应商一致 |
| 连接被拒绝 | 本地网关是否启动、端口是否冲突、工具是否指向正确端点 |
| 请求成功但没有统计 | 请求是否经过 PHI 支持的采集路径，工具与统计筛选是否对应 |

仍有问题时，使用 [Bug 模板](https://github.com/GoatGit/phi/issues/new?template=bug_report.yml)，提供 PHI 版本、系统与架构、CLI 版本、最小复现步骤和经过脱敏的错误信息。不要上传完整数据库、OAuth 文件、配置备份或未经检查的日志。

## 数据与更新

配置与数据库默认位于 `~/.phi/`（数据库为 `phi.db`）；目录可以被设置或便携模式覆盖。旧 `~/.cc-switch/` 数据不会自动迁移。API 凭据、OAuth 文件和配置备份应视为敏感数据。本地存储不代表全部加密；启用模型请求或远程同步时，数据会发送到你配置的相应服务。

应用内「检查更新」打开 GitHub Releases。下载新安装包前可先备份配置；当前未启用应用内自动安装更新。

更多信息见[安全策略](../SECURITY.md)和[获取帮助](../SUPPORT.md)。
