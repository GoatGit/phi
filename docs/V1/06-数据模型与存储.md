# 06 · 数据模型与存储设计

> 改造级别：增强。基线为 `src-tauri/src/database/`。除下节明确列出的当前路由存储外，后续章节是待实现的 V1 契约。

## 当前路由存储（2026-10-13）

- `gateway_catalog(id=1, payload)`：带 revision 的供应商、原有策略及路由组 JSON。旧目录缺少 groups/groupId 时按空组和旧候选策略读取。整份目录先验证引用、协议、组循环/深度/候选上限，再用事务做版本比较和替换。
- `gateway_supplier_secrets(supplier_id, api_key, auth_field)`：独立资源池凭据。目录、预览和轨迹不携带密钥。此表仍是 SQLite 中的独立密钥表，**本次没有宣称完成 Keychain 迁移**；07 的凭据升级仍待实施。
- `gateway_traces(id, created_at, payload)`：目录版本、策略/组/规则快照、候选决策、分类摘要、逐次尝试和最终响应观测。created_at 为 epoch 毫秒，按时间索引，最多保留最近 1000 条。
- 内存 Runtime：按供应商+模型的负载/冷却、组轮询/权重、会话绑定、意图缓存、活跃请求。会话和用户文本仅用摘要作缓存键；不保存请求正文。目录版本使调度/会话/分类缓存隔离，进程退出后运行状态清空。

03/10 所述路由组目前落在上述目录与轨迹中。下文的 route_rules、route_decisions、route_attempts 及账本表是后续规范化存储设计，尚未用这些名称落库。

## 1. 基线与兼容

继承 providers/provider_endpoints、生态资源表、settings、proxy_config、provider_health、proxy_request_logs、model_pricing、stream_check_logs、proxy_live_backup、usage_daily_rollups、session_log_sync/session_usage_dedup、profiles。表清单以冻结源码 schema 为准，不用固定“17 表”判断迁移完整性。

基线 proxy_request_logs 已有 request_id 主键、session_id、app_type、created_at（整数时间戳）与费用字符串。迁移检查缺失列，不能重复添加 session_id，也不能仅靠 CREATE TABLE IF NOT EXISTS 升级老表。历史无法恢复的维度标记 unknown。

## 2. 首启与安全迁移

1. 用户选择迁入后停止源应用写入，通过 SQLite backup API 获取一致性副本，不只复制主 db 而遗漏 WAL。旧目录保持原样。
2. 在受限暂存区执行结构与凭据迁移（07 §3）。凭据库和 SQLite 无共同事务：先写并读回 secret，再提交引用；迁移日志保存稳定 ID/状态以便重入。
3. 校验引用、加密快照、integrity_check、外键与计数后构建干净新库，关闭连接并原子激活为 `~/.phi/phi.db`。半迁移库不能启动网关或写 live。
4. 暂存明文、旧页与 WAL/journal 清理遵守 07；加密回滚包保留 7 天，恢复也必须进入安全格式，不以保留明文继续运行作为失败回退。
5. phi 迁移使用 v100 专用段；每阶段有版本记录和事务，跨凭据库步骤用日志补偿。新建库与老库升级收敛到同一 schema。

## 3. 数据契约与核心 DDL

所有新增 `*_at`、`ts` 使用 UTC Unix 毫秒；基线秒级时间戳在访问边界显式转换。金额为十进制字符串，Rust decimal 校验和累计，禁止 SQLite REAL 金额运算。以下 DDL 是待实现的核心设计；扩展基线列需迁移器先检查存在性。

proxy_request_logs 扩展 agent、project_id（在线固定归属）、project_path（显示）、reporting_project_id（事后归因）、attribution_source、usage_source、cost_source。session_id/request_id 复用。该表是请求级投影，route_attempts 是尝试账本权威，禁止同时累加二者；旧会话导入不进入网关预算。

```sql
CREATE TABLE projects (
  id TEXT PRIMARY KEY, display_path TEXT NOT NULL, created_at INTEGER NOT NULL
);
CREATE TABLE ingress_bindings (
  id TEXT PRIMARY KEY, token_secret_ref TEXT NOT NULL UNIQUE,
  agent TEXT, tool TEXT NOT NULL, project_id TEXT REFERENCES projects(id),
  route_scope TEXT NOT NULL, enabled INTEGER NOT NULL DEFAULT 1
);
CREATE TABLE project_routes (
  project_id TEXT NOT NULL REFERENCES projects(id), tool TEXT NOT NULL,
  primary_provider TEXT NOT NULL, queue_json TEXT NOT NULL,
  revision INTEGER NOT NULL, PRIMARY KEY(project_id, tool)
);
CREATE TABLE route_rules (
  id INTEGER PRIMARY KEY AUTOINCREMENT, tool TEXT NOT NULL,
  priority INTEGER NOT NULL DEFAULT 100, conditions TEXT NOT NULL,
  action TEXT NOT NULL, enabled INTEGER NOT NULL DEFAULT 1,
  revision INTEGER NOT NULL, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
CREATE TABLE route_decisions (
  request_id TEXT PRIMARY KEY, ts INTEGER NOT NULL,
  binding_id TEXT, tool TEXT, agent TEXT, project_id TEXT, session_id TEXT,
  primary_provider TEXT, chosen_provider TEXT,
  route_revision TEXT NOT NULL, rule_hits TEXT NOT NULL,
  candidates TEXT NOT NULL, reason_codes TEXT NOT NULL,
  state TEXT NOT NULL CHECK(state IN ('pending','completed','blocked','failed','interrupted')),
  latency_ms INTEGER, via_budget INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_rd_ts ON route_decisions(ts);
CREATE TABLE route_attempts (
  request_id TEXT NOT NULL REFERENCES route_decisions(request_id),
  attempt_no INTEGER NOT NULL, provider_id TEXT NOT NULL,
  account_id TEXT, model TEXT, started_at INTEGER NOT NULL, ended_at INTEGER,
  state TEXT NOT NULL CHECK(state IN ('started','completed','failed','interrupted')),
  reason_code TEXT, response_committed INTEGER NOT NULL DEFAULT 0,
  input_tokens INTEGER, output_tokens INTEGER,
  cache_read_tokens INTEGER, cache_creation_tokens INTEGER,
  usage_source TEXT NOT NULL CHECK(usage_source IN ('reported','estimated','unknown')),
  cost_source TEXT NOT NULL CHECK(cost_source IN ('price_table','provider_reported','unknown')),
  price_snapshot_json TEXT, estimated_cost_usd TEXT,
  reported_amount TEXT, reported_currency TEXT, budget_cost_usd TEXT,
  PRIMARY KEY(request_id, attempt_no)
);
CREATE TABLE budgets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  scope TEXT NOT NULL CHECK(scope IN ('global','project','agent')),
  scope_value TEXT,
  window TEXT NOT NULL CHECK(window IN ('daily','monthly')),
  limit_cost TEXT, limit_tokens INTEGER CHECK(limit_tokens >= 0),
  action TEXT NOT NULL CHECK(action IN ('warn','block')),
  enabled INTEGER NOT NULL DEFAULT 0, created_at INTEGER NOT NULL,
  CHECK(limit_cost IS NOT NULL OR limit_tokens IS NOT NULL),
  CHECK((scope='global' AND scope_value IS NULL) OR
        (scope<>'global' AND scope_value IS NOT NULL))
);
CREATE TABLE budget_usage (
  budget_id INTEGER NOT NULL REFERENCES budgets(id),
  window_start INTEGER NOT NULL, window_end INTEGER NOT NULL,
  settled_cost_usd TEXT NOT NULL, settled_tokens INTEGER NOT NULL,
  unknown_cost_attempts INTEGER NOT NULL, unknown_token_attempts INTEGER NOT NULL,
  PRIMARY KEY(budget_id, window_start)
);
CREATE TABLE budget_attempts (
  budget_id INTEGER NOT NULL REFERENCES budgets(id),
  window_start INTEGER NOT NULL, request_id TEXT NOT NULL, attempt_no INTEGER NOT NULL,
  accounted_cost_usd TEXT, accounted_tokens INTEGER,
  PRIMARY KEY(budget_id, request_id, attempt_no),
  FOREIGN KEY(request_id, attempt_no) REFERENCES route_attempts(request_id, attempt_no)
);
CREATE TABLE config_operations (
  id TEXT PRIMARY KEY, agent TEXT NOT NULL,
  state TEXT NOT NULL CHECK(state IN ('prepared','applying','completed','compensating','conflict','failed')),
  manifest_ciphertext BLOB NOT NULL, encryption_key_ref TEXT NOT NULL,
  crypto_version INTEGER NOT NULL, nonce BLOB NOT NULL, created_at INTEGER NOT NULL
);
CREATE TABLE config_versions (
  id TEXT PRIMARY KEY, agent TEXT NOT NULL, file_path TEXT NOT NULL,
  existed INTEGER NOT NULL CHECK(existed IN (0,1)), content_hash TEXT NOT NULL,
  content BLOB NOT NULL, encryption_key_ref TEXT NOT NULL,
  crypto_version INTEGER NOT NULL, nonce BLOB NOT NULL,
  change_source TEXT NOT NULL CHECK(change_source IN ('phi','external','import','restore')),
  baseline_state TEXT NOT NULL CHECK(baseline_state IN ('observed','native_verified','unknown')),
  operation_id TEXT REFERENCES config_operations(id), provider_id TEXT,
  restored_from TEXT REFERENCES config_versions(id), created_at INTEGER NOT NULL
);
CREATE INDEX idx_cv_file ON config_versions(agent, file_path, created_at);
CREATE TABLE usage_rollup_dimensions (
  day TEXT NOT NULL,
  dimension TEXT NOT NULL CHECK(dimension IN ('project','agent','model','account')),
  dim_value TEXT NOT NULL,
  input_tokens INTEGER NOT NULL, output_tokens INTEGER NOT NULL,
  cache_read_tokens INTEGER NOT NULL, cache_creation_tokens INTEGER NOT NULL,
  cost_usd TEXT NOT NULL, unknown_usage_attempts INTEGER NOT NULL,
  unknown_cost_attempts INTEGER NOT NULL, requests INTEGER NOT NULL, attempts INTEGER NOT NULL,
  PRIMARY KEY(day, dimension, dim_value)
);
CREATE TABLE billing_adjustments (
  id TEXT PRIMARY KEY, account_id TEXT NOT NULL,
  period_start INTEGER NOT NULL, period_end INTEGER NOT NULL,
  currency TEXT NOT NULL, billed_amount TEXT NOT NULL, created_at INTEGER NOT NULL,
  CHECK(period_end > period_start), UNIQUE(account_id, period_start, period_end, currency)
);
```

### 3.1 事务与聚合

- 每个连接启用 foreign_keys。入口先提交摘要，上游调用前提交 attempt；终结事务更新 attempt、请求投影、预算累计及维度汇总，按复合主键幂等。进程重启把遗留 started/pending 标记 interrupted 和未知用量，不伪造零费用。
- budget_attempts 保存已计入值；迟到 usage 按旧新差额更新，去重行与累计必须同事务。预算启用回填走同一路径，窗口固定为请求接入窗口。未知计数的增加/消除同样幂等。
- 四个报告维度独立透视，不能横向相加；项目×模型交叉筛选回到有界明细。unknown 使用保留值。requests 按 request_id 去重，多模型/账号尝试可跨桶重复，跨桶费用与 attempts 可勾稽，requests 不能简单相加。
- 归因补录重建报告维度，不改在线预算和决策。当月预算、未结束/未知尝试及待核实记录不可随 30 天日志清理丢失。
- JSON 用版本化类型校验，不能执行任意条件代码。provider 引用采用 app_type 命名空间；route_revision 保存规则与绑定版本，支持回放原因。

### 3.2 配置与凭据

config_versions.content 是 zstd 后 AEAD 密文；不存在文件也保存带 existed 标记的加密空载荷。content_hash 为安装级 HMAC，nonce 按密钥唯一，AAD 绑定类型、版本和稳定记录 ID。config_operations 的加密 manifest 保存文件清单、受管字段前后值、预期摘要与各文件完成状态，供 04 的恢复、重入与补偿使用。

providers/settings/profiles 中结构化凭据改为 secret_ref；无法安全拆分的 payload 和 proxy_live_backup 使用相同加密封套。这是必做迁移，不能仅新增配置历史表。引用和备份清单由 phi-secrets 服务维护，相关版本和备份仍存活时不得删除密钥。

## 4. 访问、同步与备份

DAO 经 Service 写入，commands 保持薄层。核心日志持久化失败必须可见；异步队列只刷新通知/缓存。报表使用对应维度汇总或有界分页，不强迫不匹配维度的查询走 rollup。

- 决策历史默认 30 天；配置最近 50 版加可信 baseline，操作补偿/恢复/备份仍引用的版本保留。清理按外键顺序事务执行。
- 普通数据库备份依赖可解锁的本机凭据库，明确标为非完整灾备；保留清单保护备份依赖 secret，避免密钥轮换使备份失效。
- 完整跨设备备份显式导出口令加密包，包含 schema/加密版本、数据库、所引用 secret 和快照密钥；使用 07 的口令派生及 AEAD。导入在隔离区验证并重映射本机引用后激活，不留下明文临时包；口令不可恢复。
- WebDAV/S3 仅同步非敏感允许字段及逻辑 credential slot，排除本机引用、完整快照、操作记录、账本和保险库。导入重新绑定凭据，缺失时为 needs_credentials，不能转发或写 live。

## 5. 验收

- 冻结版本真实 schema 的合成库与新建库一致；覆盖已有 session_id、WAL 未 checkpoint、多工具同 provider ID、未知历史维度。
- 逐阶段 kill 后重入；secret 写成功但事务失败、锁库、引用缺失、AEAD 篡改均不能激活半迁移数据。
- 多尝试、重复完成、迟到 usage、跨日流、预算回填与维度重建勾稽一致；请求数/尝试数/未知量分别验收。
- 完整包换机恢复；普通备份失去凭据库、错误口令、损坏包均明确失败。
- DDL 语法检查仅证明设计片段可建表，实现仍需真实迁移、事务并发及业务约束测试。

## 实施 ADR：权威账本首版存储（2026-10-13）

- 当前表以 `ledger/schema.sql` 为准：`route_decisions`、`route_attempts`、`budgets`、`budget_usage`、`budget_attempts`、`budget_alerts`、`billing_adjustments`、`ledger_metadata`、`ledger_daily_dimensions`、`ledger_request_rollups`；独立 `phi_schema_migrations` 版本 100 记录账本起点，不复用 fork 的 `user_version=21`。
- 请求和尝试使用索引列 + 强类型 JSON payload，金额为 Decimal 字符串。预算按尝试保存已计金额/Token 与部分用量标识，同一事务更新尝试、请求摘要、预算累计和报表贡献；迟到用量和重复结算均走差量路径。
- `projects`、`ingress_bindings` 保存可信归因。自定义本地令牌仅存 verifier；这不代表上游 secret 已迁移。
- 上述本机表全部从 WebDAV/S3 导出排除，同步导入保留本机数据和账本起点。普通完整 SQL 备份仍属旧机制，**尚不能宣称是安全加密备份**。
- 当前权威明细不主动裁剪。迁移 101 为既有权威请求回填 UTC 维度汇总及请求贡献；之后结算和报表归因变更以旧新贡献差量更新，完整日汇总与边界日贡献互斥读取。后续若引入清理，仍须定义未知记录保留、预算重建与归因变更期限，不能仅删除明细。旧网关日志/rollup 无法恢复逐尝试语义时，拒绝在不完整窗口启用预算，不能视为零用量。

`route_decisions.reporting_project_id` 只服务于报表筛选，payload 同时保存 `attributionSource` 和 `reportingAssignedAt`；在线 `project_id` 不变。`ledger_metadata.legacy_until` 固化账本前历史缺口，`system_notifications` 保存本机通知偏好；两者均不随配置同步。`budget_alerts.notified_at` 表示已尝试本机投递，不表示操作系统确认展示。
