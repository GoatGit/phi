# 07 · 凭据与安全设计

> 改造级别：**新建（phi-secrets）+ 增强（审计）**。基线事实：API Key 明文存于 SQLite `providers` 表；系统 Keychain 仅用于部分 OAuth token（Codex/Claude 订阅、Copilot、xAI）；网关默认监听 127.0.0.1；前端 CSP 已配置（tauri.conf.json）。

---

## 1. 威胁模型（本地单机）

| 资产 | 威胁 | V1 对策 |
|---|---|---|
| API Key（明文 SQLite） | 本机恶意软件/误共享 `~/.phi/` 目录/备份外泄 | Keychain 迁移（§3） |
| OAuth token | 同上（部分已入 Keychain） | 统一收敛到 phi-secrets |
| 请求日志/账本 | 隐私泄漏 | 内容不入库默认（05 §5）+ 脱敏（§4） |
| 网关端口 | 局域网内未授权调用 | 回环默认 + 新增统一鉴权 + 加密远程接入（§3.4） |
| 更新通道 | 中间人/假更新 | 更新签名密钥轮换（§6） |
| 配置文件注入 | Agent live 配置被篡改 | 版本化 + hash 检测（04 §2） |

## 2. phi-secrets crate（D2 载体）

- 首选 keyring（macOS Keychain / Windows Credential Manager / Linux Secret Service）；接口按随机 secret ID 提供 put/get/delete，不按 provider ID 限制为单密钥。
- 系统凭据库不可用时，提供会话内存模式或用户口令保险库：Argon2id（随机盐、版本化参数）派生密钥，AES-256-GCM 包装随机 256 位主密钥。主密钥不得与密文一起明文保存；机器标识不是秘密材料，不参与保密保证。锁定时停止依赖保险库的操作，不回退明文。
- 结构化凭据只存 secret_ref；完整配置快照必须先压缩再 AEAD 加密，独立 nonce，AAD 绑定记录 ID、类型和格式版本。密钥由 phi-secrets 保存，解密失败禁止恢复。
- 安全承诺限于 phi 管理的持久化存储。Agent 必需的 live 文件可含明文，按最小权限写入；用户旧应用目录、系统备份不在清零范围内。不能承诺防御已经控制当前用户进程的攻击者。

## 3. 凭据全生命周期（G2）

### 3.1 迁移与回滚

1. 迁移清单覆盖 providers.settings_config、profiles.payload、proxy_live_backup、settings 认证值、OAuth 缓存与 config_versions。适配器按字段路径识别 API Key、access/refresh token 和本地令牌；未知格式完整快照一律加密，不能只依赖密钥前缀。
2. 停写后用 SQLite backup API 创建一致性副本，在受限暂存目录迁移，旧应用目录不动。回滚材料必须是加密包，禁止留下明文 phi.db.bak。
3. 每个凭据分配稳定随机 ID，先写凭据库并读回校验，再事务性替换 JSON 中的凭据字段。迁移日志仅存 ID 和状态；中断按 ID 重入，孤立 secret 延迟清理，不激活半迁移库。
4. 从已迁移数据构建干净新库，校验引用和完整性后关闭连接并原子替换；清理 phi 暂存库、旧页、WAL/journal、明文导出。删除不等于 SSD 物理擦除，外部历史副本需提示用户轮换凭据。
5. 凭据库失败停在向导；不允许保留明文继续运行 phi。会话模式不持久化旧凭据或快照，无法持久保存恢复材料时禁用 live 接管写入。
6. 加密回滚包保留 7 天，回滚仍解锁并迁入当前安全格式，不重新激活明文库。secret 及快照密钥须保留到全部历史版本和本地备份引用到期。

### 3.2 审计

已新增 scripts/audit_no_plaintext_secrets.py 的结构/合成 canary 检查；完整加密迁移验收仍待实现：按字段清单验证引用化，用含无前缀随机凭据的合成 fixture 检查数据库、WAL/journal、导出及日志；验证解压/解密路径只在授权内存中出现明文，完整快照未以压缩明文落盘。前缀扫描仅为补充。

报告分别列出 phi 管理存储、受管 live 文件及未修改的旧目录。CI 不访问真实凭据；覆盖迁移中断、锁定、篡改、引用缺失、轮换和备份恢复。

### 3.3 OAuth、同步与备份

- OAuth 统一走 phi-secrets；官方账号透传凭据仅存在于请求内存，不进入日志或配置历史。
- WebDAV/S3 仅同步允许清单内的非敏感配置，不传本机 secret_ref、完整快照、保险库或运行账本。逻辑 credential slot 在目标设备重新绑定，缺失时标记 needs_credentials，禁止转发及写 live 占位凭据。
- 普通数据库备份不包含凭据灾备能力。跨设备完整恢复须显式导出口令加密包，包含版本清单、数据库、必要 secret 和快照密钥；导入生成本机引用，校验全部依赖后激活。忘记口令无法恢复。详见 06 §4。

### 3.4 网络面与统一鉴权

**信任边界（2026-10-13 修正）**：PHI V1 是个人桌面网关。入站令牌用于识别客户端请求、绑定账本/预算归属、限制持有该令牌的请求范围及撤销接入，不代表已经识别某个真实用户或可执行程序，也不隔离能操作同一份 PHI、读取客户端令牌或修改其数据的同机进程/使用者。另一个人安装 PHI 不等于获得本实例的配置；真正的同机用户隔离依赖独立系统账户和文件权限，多人租户及管理面鉴权不在 V1 范围内。

内置应用接入时自动配置本地令牌，普通使用流程不要求手工签发。路由页已移除“高级：其他客户端接入”及其手工签发入口；原功能用于本人 Cline、Continue 或脚本等通用客户端，不属于内置应用连接所需步骤。已有绑定、令牌验证及后端兼容能力保留；移除入口不改变网关的前置鉴权，回环 HTTP 也不能因此改为匿名。

基线仅 Claude Desktop 专用入口校验 gateway token；普通 Messages/Chat/Responses/Gemini 未统一鉴权，PROXY_MANAGED 是占位符。

- V1 新增统一前置鉴权，先于请求体读取及转发，覆盖 models、status、流式、WebSocket 握手、全部别名与通配路由；仅 /health 可匿名返回无账号和配置信息的存活状态。缺失/错误令牌返回 401，不能调用上游。
- 每接入绑定签发至少 256 位随机令牌，凭据库存储、恒定时间比较、支持撤销轮换。Chat/Responses 使用 Authorization: Bearer，Messages 使用 x-api-key，Gemini 使用 x-goog-api-key；拒绝 URL query 中的本地令牌。
- 验证后剥离所有本地认证头，按选定上游凭据重新构造认证，不把本地令牌透传到供应商。接入绑定限定允许工具与路由范围；路径或客户端 header 不可覆盖绑定权限。
- 官方 Codex 需保留上游 Authorization 时，本地令牌单独使用 x-phi-token；客户端配置始终生成支持该 header 的 custom 官方镜像路由，不依赖“统一 Codex 会话历史”开关。官方登录保留在原认证存储中，切回直连按原偏好恢复 openai 或 custom；不因切换代理修改偏好或迁移既有会话。旧版 openai_base_url 改道仅用于识别和恢复，不再生成缺少本地认证头的官方代理配置。多种本地令牌来源同时出现时拒绝。x-phi-token 始终剥离，上游官方凭据只发送到适配器校验的官方端点，不得故障转移泄漏到第三方。
- 回环监听也必须鉴权。V1 没有内置入站 TLS 时，远程访问只支持显式配置的 TLS 反向代理/加密隧道转入回环端口，拒绝直接绑定 LAN/公网明文 HTTP；远程模式不支持官方凭据透传。CORS 不能替代认证。
- 出站 TLS 继承 rustls 校验，自带 CA 显式配置；保险库锁定或令牌恢复失败必须拒绝请求，不能关闭鉴权。

## 4. 日志与遥测

- 脱敏规则（继承基线思路，扩展）：日志与决策日志中，`authorization`/`x-api-key`/`api-key`/`x-goog-api-key`/`x-phi-token` 头、URL 中的 key 参数、请求体中的凭据字段一律 `***`；黄金集录制文件同样脱敏后才可入库 git（默认不入）；
- **遥测立场**：phi 默认零遥测；崩溃上报为显式 opt-in，内容仅堆栈与版本，发送前可预览（本地优先原则的产品化表达）；
- 日志文件位置与保留期在设置页可见、可一键清除。

## 5. 订阅账号合规立场（D5）

基线包含 Codex OAuth、Claude 订阅（ClaudeAuth）、Copilot、xAI OAuth、Gemini 等"官方账号直连"能力，且是"凭据自由"的重要组成。phi 的立场：

1. **保留能力**：用户接入**本人**有权使用的订阅账号，属核心体验（模型自由/凭据自由），V1 不裁剪；
2. **透明声明**：订阅接入页固定展示——"直连官方订阅需遵守该供应商服务条款；条款与风控政策由供应商单方决定，使用风险由用户自担"；各供应商条款链接可查；
3. **红线**：不做账号共享、不做多人合租、不做规避地区/额度限制、不做转售（继承 V0 合规优先原则）；
4. **法务时点**：M3（GA 决策）前完成一次外部合规评审，覆盖：订阅直连表述、MIT 合规、隐私声明、更新通道安全。

## 6. 供应链与更新安全

- **更新签名**：fork 后**必须更换** Tauri updater 签名密钥对（不复用上游公钥信任），新公钥随首个 phi 版本分发；`tauri.conf.json` 的 `createUpdaterArtifacts` 与 endpoint 指向 phi 自有服务器（08 §3）；
- **依赖**：`cargo auditable`（构建时嵌入依赖清单）+ `cargo deny`（许可证与 CVE 检查）纳入 CI；
- **构建**：GitHub Actions 三平台（继承），发布产物附 SHA256 清单。

## 7. 验收要点

- 全新安装与迁移安装两条路径下，`audit_no_plaintext_secrets` 通过；
- keyring 不可用时验证口令保险库/会话模式，锁定、错口令、篡改和缺失引用均失败关闭；
- 全部端点及别名认证测试通过，本地令牌与官方透传凭据不泄漏；
- 换机同步进入 needs_credentials；加密完整备份可恢复，普通 SQL 备份标明凭据限制；
- 日志/账本/决策日志抽样无明文密钥与请求内容（默认配置下）；
- 订阅接入页声明文案存在且不可跳过（首次使用确认一次）；
- 更新签名公钥与上游不同，假更新包无法通过校验（测试注入验证）。

## 实施 ADR：自定义接入令牌（2026-10-13）

`access.rs` 为通用客户端签发至少 256 位随机令牌，仅一次返回明文；SQLite 保存 SHA-256 验证摘要，验证时恒定时间比较，支持轮换/停用。此类令牌不需要从服务端重新取回，因此采用 verifier 而非可逆凭据引用；用户遗失后轮换。自动写客户端配置的内置应用令牌仍是进程级，不在此变更中改为持久保存。

绑定限定 Agent、协议、项目和路由组；scope 更改同时改变会话缓存命名空间。通用令牌不支持官方 Codex Authorization 透传，不能把 x-phi-token 与另一枚本地令牌叠加。全入口鉴权仍先于正文读取。

这里的 Agent 是由本机管理者设置的记账标识，项目是该令牌的预算归属；都不是对客户端程序或系统用户身份的认证。原手工表单区分“全部路由”和“仅指定路由组”，后者未选择有效组时禁止提交，切换协议也不得静默扩大范围。此表单的路由页入口现已移除，不应继续引导用户在此创建令牌或登记项目。

上游 API Key、OAuth、Profiles、live-state 和完整数据库备份的统一安全迁移尚未完成；此 ADR 只解决自定义入站令牌的存储。

审计脚本使用显式 `--database` 库副本，并可提供 `--canaries-file` 合成随机凭据及 `--artifact` WAL/日志/导出副本。引用须由 `--references-file` 提供已验证 ID；无法解析配置、缺失引用和无法证明加密的快照均报错。CI 目前运行 4 项合成检测样例，只证明扫描与报告逻辑，不证明当前 PHI 已无明文。真实迁移、AEAD 校验、解锁和密钥生命周期测试仍是安全发布的前置条件。
