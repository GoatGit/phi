# 05 · 账本与观测设计

> 改造级别：**增强**。基线：`proxy/usage/{parser,calculator,logger}.rs`、`proxy_request_logs`、`usage_daily_rollups` + `dao/usage_rollup.rs`、`model_pricing` + `services/model_pricing.rs`、`services/{usage_stats,usage_cache,balance}.rs`、6 个 `session_usage_*` 服务。

## 当前路由观测实现（2026-10-13）

本次交付 `gateway/analytics.rs` 与路由状态/请求记录页面，数据来自 `gateway_traces`。当前保留最近 **1000 条请求**；筛选窗口不会补回已删除的记录，界面显示最早保留时间。按应用、组、策略、结果过滤后，计算已结束请求的完成/失败/中断、故障转移、P50/P95、已知输入/输出 token、估算费用及未知记录数，分页每页 50 条。进行中请求单独显示，不计入完成率分母。

费用使用已有价格表与 Decimal。主请求费用来自最终响应；失败尝试只有结果与耗时，尚无完整 usage 结算。意图分类调用单列次数、用量、耗时和估算费用，缓存命中不重复计费。未知费用不当成已结算零值；已知费用合计旁展示未知数。原始请求/响应正文不持久化。

运行状态（活跃数、冷却、尝试计数、衰减用量）只在当前进程中维护；日志关闭仍可查看实时状态。重启前未完成的持久化请求在报表中标为中断。下述权威账本已有独立实现，不能用可清理的路由统计替代预算累计。

## 权威账本实施（2026-10-13）

`ledger.rs`、`proxy/ledger_observer.rs` 和 `access.rs` 已接入真实 handler/forwarder；分类器也是独立尝试。每次上游调用前冻结实际出站模型单价和倍率，失败/重试分别结算，请求接入时 UTC 窗口固定。请求 ID 与路由快照一致，策略及候选快照保存在账本，不依赖 `gateway_traces` 保留期。

已实现 2/3/4 节的可信绑定、预算阈值、幂等回填和手动账单核对。流式部分 usage 保留为已知下界，并以 `usage_complete=false` 保留未知计数；费用/Token block 不会因收到部分 usage 提前解除。完整 usage 迟到补齐时，以差量替换未知，不重复计费。

报表按 Decimal 计算，完整 UTC 日使用持久维度汇总，首尾不完整日使用请求贡献；权威明细暂不裁剪。已知费用和未知次数并列显示；无账号绑定保留 unknown，不能猜成供应商账号。账单录入支持非 USD 原币展示，但只有 USD 计算差额；覆盖不全、未知账号或未结束窗口明确提示。UI/系统通知的窗口去重及显式项目 reporting 归因已接入，具体口径见文末；自动会话关联仍待补。

## 1. 基线盘点：账本的地基已经存在

| 能力 | 基线实现 | 说明 |
|---|---|---|
| 请求级落库 | `proxy_request_logs` 表 + `usage/logger.rs` | 每请求记录 Token、耗时、状态、provider |
| Token 解析 | `usage/parser.rs` + **rquickjs 脚本** | 各供应商响应格式的用量抽取以 JS 脚本实现（可热更新的经验层） |
| 计价 | `usage/calculator.rs` + `model_pricing` 表 | 按 price 表计算费用（rust_decimal 精确小数） |
| 汇总 | `usage_daily_rollups` + `dao/usage_rollup.rs` | 日粒度聚合，报表底座 |
| 会话级观测 | `session_usage_{codex,gemini,grokbuild,mcode,opencode,pi}.rs` | 直接解析各 Agent 本地会话文件，产出"步骤/命令/文件/Token"级视图（`session_log_sync`、`session_usage_dedup` 防重） |
| 额度视图 | `services/balance.rs` | 供应商余额/额度查询 |
| 缓存 | `usage_cache.rs` | 报表查询缓存 |

**判断**：V0 设想的"请求级 Token 与费用记录"在基线已实现约 70%。V1 的账本工作不是从零建账，而是补三件事：**归因、约束（预算）、口径（可信度标注）**。这与"账本是延伸体验"的定位一致——投入克制，但要让延伸体验达到可付费质量。

## 2. 归因模型（G3）

### 2.1 维度

每个请求归因到：

| 维度 | 来源 | 说明 |
|---|---|---|
| agent / tool | 已认证接入绑定 | inbound 只标识协议，不能区分共用入口的 Agent |
| session_id | `proxy/session.rs::extract_session_id`（继承，多来源） | 会话串联 |
| **project_id / project_path** | 预先注册的接入绑定；本机会话关联仅作事后补充 | 稳定 ID 用于预算和路由，路径只作显示 |
| provider / model | 请求路径 | 花在哪 |
| provider_account | provider 绑定 | 哪个账号 |

实现：新增 ingress_bindings 将本地令牌映射到 agent、tool、project_id 与路由授权范围；绑定由本机用户配置。网关生成 request_id；基线 session_id 已存在，不能重复加列。会话 ID 按绑定命名空间隔离；客户端自报的路径/会话只能是 hint，不能提升路由权限或规避预算。

没有可信项目时在线归因记 unknown，仍执行全局及已知 Agent 预算；启用项目 block 预算的接入必须绑定项目，否则拒绝并提示配置。事后扫描只更新 reporting_project_id 与归因来源/置信状态，不改变当时预算归属或路由决策。报表展示未知维度，可归因率以全部已受理业务请求为分母，不删除未知项美化指标。

### 2.2 报表（V1 范围）

- **本月视图**：按 项目 / Agent / 模型 / 账号 四个透视维度的费用与 Token（数据源 `usage_daily_rollups` 扩列）；
- **请求流视图**：继承基线请求日志列表，增加归因筛选器；
- **会话视图**：继承 `session_manager` + `session_usage_*`（fork 已相当完善，仅品牌化）；
- 不做：团队成本分摊、跨设备合并报表（V1 非目标）。

## 3. 预算阈值拦截（G3）

V1 明确采用**已结算阈值拦截**，不是严格费用硬上限。单次长流、在途并发、失败尝试及上游账单差异都可能导致超支。UI 必须在 block 开关旁说明：达到已结算阈值后拒绝新的上游尝试，不能保证最终费用不超过额度。严格预留/结算方案留待后续 ADR。

- 全局、Agent、项目的所有匹配预算同时检查，任意 block 命中即拒绝 429；warn 告警去重。按 UTC 日/月半开窗口计数，UI 展示 UTC；一次请求及全部尝试归属请求接入时窗口，跨日长流不会换窗口。
- 每个尝试结束后，在同一 SQLite 事务中幂等更新 attempt 用量、请求汇总、budget_usage 与派生汇总；不执行“rollup + 未标记明细”双计累计。检查必须读取已提交的 budget_usage；在途量另行展示。存储失败时 block 拒绝后续尝试并标记异常，不把失败当零费用。
- 未知价格不是免费。费用 block 遇到 UNPRICED 拒绝尝试；token block 遇到未知 token 累计拒绝后续尝试，费用 block 遇到 usage_unknown 同样拒绝，直至用户核实或显式切换 warn。warn 可放行但展示覆盖缺口。限额非负，至少设置 cost 或 tokens 一项。
- 开启预算时按当前窗口既有权威明细回填，完成后才启用；明细已过保留期且无法完整重建时不允许假装从零开始。预算阈值编辑不重置累计；范围/窗口变更创建新预算并回填。所有金额使用 rust_decimal，不用 SQLite REAL/SUM 浮点计算。
- 上游失败可能仍计费。各尝试分别结算已知 usage，未知标记待核实；客户端断开也执行完成/中断记录。请求计数在请求摘要层计一次，尝试数另列。
- 不按预算自动改路由；通知仅 UI + 系统通知。预算阻断仅约束经过 phi 的流量。

## 4. Token 与费用口径

Token 来源和费用来源分开记录，不能把上游返回 usage 视作供应商已报告费用：

- usage_source = reported / estimated / unknown；记录输入、输出、缓存读取和缓存创建，适配器统一包含/排除关系，避免重复加缓存 token。
- cost_source = price_table / provider_reported / unknown；普通 usage 通过价格表计费仍为 price_table。provider_reported 只允许明确给出金额、币种且已验证语义的接口；不是自动对账。
- 每个 attempt 固化 model、account_id、价格版本与倍率、估算金额及可选供应商金额。V1 预算统一 USD；非 USD 的供应商金额单独展示，未配置明确汇率时不替代预算金额。缺失值为 NULL 而不是 0，UI 展示未知。
- 默认报表费用为价格表估算，不因价格表后续编辑重算历史。手动校准存 billing_adjustments（账号、UTC 周期、币种、账单金额），仅展示同范围已知估算与账单偏差，不篡改逐请求费用和预算累计。
- 会话文件与代理日志分来源保存；只有稳定请求标识匹配才能合并展示，不能以时间接近猜测去重。V1 预算与主费用报表只取网关 attempt 账本；未匹配的本地会话统计单独显示，避免双计。

## 5. 数据边界（原则，写入产品文案）

- **请求/响应内容默认不入库**：`proxy_request_logs` 与决策日志只存元数据与用量；内容级调试（黄金集录制、请求查看器）是显式开关 + 本地存储 + 醒目提示（02 §4.1、07 §4）；
- 账本数据在 `~/.phi/phi.db` 本地存储；WebDAV/S3 仅同步非敏感配置允许清单，不同步运行账本、设备凭据引用或完整快照（07 §3.3）。

## 6. 验收要点

- 每个已受理请求展示项目/Agent/会话/模型/费用/原因及未知状态；测试共享入口、多项目并发、伪造提示、迟到关联和缺失绑定；
- 归因率 ≥80%（验证期实测）；日汇总与请求明细勾稽一致（抽样脚本）；
- 预算 block 生效：超限请求被拒、Agent 可识别、决策日志有 `BUDGET_BLOCK`；
- 月度估算偏差手动校准流程跑通（含 `UNPRICED` 提示路径）；
- 默认状态下数据库与日志无请求/响应正文数据（审计实际内容，不以列是否存在代替）。

## 当前实施口径（2026-10-13）

- 网关账本独立于会话导入与诊断日志；逐尝试价格快照、已知部分用量和未知覆盖并存。取消后的部分 usage 不会清除未知计数；完整迟到 usage 才能消除缺口。
- 已实现项目/Agent/模型/账号四维 UTC 日汇总，结算和补录以请求贡献差量更新；完整日与首尾不完整日互斥读取。查询默认本月，最多 366 天，每页 50 条。
- 已结束、在线项目未知的请求可在详情中手动补充报表项目，保存来源和时间。在线预算、接入身份和策略快照保持原始值；自动会话扫描关联未接入。
- warn/block 告警在受理检查及结算达到阈值时落库，按预算/窗口/原因去重。UI toast 与预算历史提示已接入；系统通知默认关闭，原生端独立于主窗口投递，受操作系统设置控制。
- 账单核对记录账号、UTC 周期、原币种金额，只比较已知估算，不修改历史价格或预算。非 USD 不隐含换汇，覆盖不完整时明确提示。
- 预算和账单金额输入使用普通非负小数字符串，提交前校验 Decimal 的 96 位尾数、最多 28 位有效小数，禁止浮点舍入、科学计数法及溢出。Token 限额输入不得在验证安全整数之前转成已舍入的草稿值。账单日期使用可清空的字符串草稿，验证真实日期、UTC 零点、结束晚于开始及最多 366 天后提交；删除账单确认仅影响核对记录。
- 持久汇总已实现，但保留期清理策略尚未启用；权威明细暂不裁剪。归因率和真实账单偏差仍需要验证期数据，不能用合成测试填报。
