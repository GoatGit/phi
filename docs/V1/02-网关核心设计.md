# 02 · 网关核心设计（phi-gateway）

> 改造级别：**继承为主 + 黄金集保障 + 定点增强**。基线：`src-tauri/src/proxy/`（约 40 个模块）。

---

## 1. 范围

本文定义 phi 网关（请求接入、协议互转、上游转发、流式处理、用量采集挂钩）的 V1 设计。路由决策与故障转移策略见 03；用量落库与计价见 05。

## 2. 基线能力盘点（来自源码）

### 2.1 服务器与请求路径

- 进程内 axum 服务器：`server.rs` 以 `tokio::net::TcpListener::bind(listen_address:listen_port)` 启动（端口可配，支持 0=随机端口），启动后 `http_client::set_proxy_port` 注入出站端口；
- 请求路径：`handlers.rs`（按 inbound 协议分发）→ `handler_config/handler_context`（组装上下文）→ `provider_router.rs`（选 provider）→ 适配器转换 → `forwarder.rs`/`hyper_client.rs`（出站）→ `response_processor.rs` + `sse.rs`（回放）→ `usage/`（采集）；
- 会话识别：`session.rs::extract_session_id` 从请求中提取会话 ID（多来源 `SessionIdSource`），是账本归因的现成地基。

### 2.2 inbound（Agent 侧）协议

| inbound | 对应 Agent | 说明 |
|---|---|---|
| Anthropic Messages | Claude Code、Claude Desktop（模型映射模式） | 主路径 |
| OpenAI Responses | Codex | 含 SSE（`codex_responses_sse.rs`） |
| OpenAI Chat | Codex、Grok Build、通用工具 | 基线已有 handle_chat_completions；V1 补通用接入契约（见 §5） |
| Gemini | Gemini CLI | `gemini_url.rs` 处理 URL 形态差异 |

### 2.3 outbound（供应商侧）适配器 `proxy/providers/`

| 适配器 | 认证形态 | 关键文件 |
|---|---|---|
| Anthropic | API Key（`x-api-key`）/ OAuth（ClaudeAuth） | `claude.rs`、`auth.rs` |
| OpenAI（Responses/Chat 双形态） | API Key / Codex OAuth | `codex.rs`、`codex_oauth_auth.rs`、`codex_direct.rs`（服务层） |
| Gemini | API Key / OAuth | `gemini.rs`、`gemini_schema.rs`、`gemini_shadow.rs` |
| GitHub Copilot | OAuth + model map | `copilot_auth.rs`、`copilot_model_map.rs` |
| xAI | OAuth | `xai_oauth_auth.rs` |

### 2.4 跨协议转换能力（`transform_*` + `streaming_*`）

模块存在不能证明任意 inbound/outbound 组合都可用，也不能将转换函数视为可逆函数。V1 维护逐路径能力清单：入口 handler → 实际选择分支 → 请求转换 → 响应/SSE 转换 → fixture ID。每个组合分别标记已验证、待验证或不支持，包含 tools、图片、Thinking、usage 与流式能力；只有黄金集通过的组合才能在 UI 宣称支持。缺失路径明确返回不支持错误，不以全互转矩阵作承诺。

非阻塞转换（流式）：`streaming_codex_anthropic / streaming_codex_chat / streaming_gemini / streaming_responses`。另有供应商特化处理：`transform_codex_chat_moonshot_schema`（Moonshot schema 兼容）、`transform_codex_responses_namespace`、`transform_codex_responses_xai_sanitize`（xAI 清洗）、`reasoning_bridge.rs`（推理字段桥接）、`inline_think.rs`、`responses_late_arguments.rs`（工具调用迟到的参数）。

### 2.5 矫正器（上游兼容性经验层，**原样继承，禁止轻动**）

`thinking_rectifier` / `thinking_optimizer` / `thinking_budget_rectifier`（Thinking 签名与预算）、`opaque_state_rectifier`（不透明状态续接）、`media_sanitizer` + `tool_media`（图片/媒体降级）、`body_filter`、`cache_injector`（缓存注入）、`json_canonical`（规范化）、`content_encoding`（压缩协商）。这些模块承载了大量"某个上游不能处理某种请求"的隐性知识，是 fork 价值最高的资产之一。

### 2.6 可靠性与可观测

- `circuit_breaker.rs`（状态机 + 统计）、`failover_switch.rs`（故障转移队列）、`switch_lock.rs`（切换互斥）、`error_mapper.rs`（错误归类）、`log_codes.rs`（日志码）、`provider_health` 表；
- `usage/{parser,calculator,logger}.rs`：请求级 Token 解析、按 `model_pricing` 表计价、落库 `proxy_request_logs` + `usage_daily_rollups`。

## 3. V1 网关需求

1. **行为兼容承诺**：已支持转换路径保持行为兼容。品牌/日志注入、缺陷修复及 G7 明确列出的新增路径均须黄金集覆盖；新增鉴权属于有意收紧的入口契约，不能以兼容性为由绕过。
2. **可解释挂钩**：在 `provider_router` 决策点与 `failover_switch` 切换点发出结构化事件（见 03 §4），网关本身不感知 UI。
3. **归因挂钩**：`usage/logger` 落库前附加归因字段（项目/Agent/会话，来源见 05 §2）。
4. **预算闸门**：统一鉴权及可信归因后、每次上游尝试前检查已结算用量；warn 放行告警、block 拒绝 429。V1 是阈值拦截，不保证在途并发或单次长请求不超支（05 §3）。
5. **监听与安全**：新增全路由统一鉴权，默认回环；远程仅支持加密入口转入回环，详见 07 §3.4。普通入口没有可直接沿用的统一认证。

## 4. 协议黄金集回归（G6，V1 硬门槛）

fork 最大的风险是"改动悄悄破坏看不见的兼容性"。对策不是重写而是**行为快照**：

### 4.1 用例来源（三路）

1. **录制**：新增独立录制挂钩，显式开关、默认关闭；不假设请求日志已具备完整请求/响应体录制能力。认证头、URL 凭据先剥离，含用户内容的录制包按 07 的 AEAD 方案加密存于 `~/.phi/golden/`，保留期默认 7 天；解密仅在授权回放内存中。导出给 CI 必须替换提示词、路径、工具结果等隐私为合成数据，并经人工确认；原始录制绝不入 git。
2. **手工构造**：边界用例——流式中断、工具调用迟到参数（`responses_late_arguments` 场景）、Thinking 签名、图片降级、上下文超限错误、429/529 重试语义、缓存命中；
3. **上游测试移植**：基线 `proxy` 模块已有大量 `#[cfg(test)]` 与 mock upstream 测试（`server.rs` 内 `mock_listener` 模式），全部保留。

### 4.2 经审查的合成用例格式（加密录制包解密后的逻辑布局相同）

```
~/.phi/golden/cases/<case-id>/
  meta.toml          # 名称、inbound/outbound、来源（recorded|crafted）、供应商
  request.json       # 规范化后的 inbound 请求（json_canonical 处理）
  response.sse       # 上游原始响应流（含分帧）
  expects/
    transform.json   # 期望的 outbound 请求（规范化 diff）
    client.sse       # 期望回放给 Agent 的流（事件序列 diff）
    usage.json       # 期望的 Token/费用解析结果
```

### 4.3 断言与 CI

- 断言基于 `json_canonical` 规范化后 diff（忽略无关字段顺序），SSE 按**事件序列**而非字节流比对；
- CI：`cargo test golden --features golden` 每次提交全量跑；改 `providers/`、`transform_*`、`streaming_*`、矫正器的 PR 必须附新增用例或说明为何不需要；
- 目标：M2 出口时 ≥ 120 个用例，覆盖全部 transform/streaming 组合与 §4.1-2 边界清单。

## 5. 通用 OpenAI Chat 接入完善（G7）

- **基线**：server.rs 已注册 /chat/completions、/v1/chat/completions 及 Codex 别名，共用 handle_chat_completions。G7 不重复建入口。
- **增量**：解除通用客户端对特定工具路由上下文的依赖，接入绑定提供路由身份；统一认证、模型发现、参数验证和错误格式。
- **转换**：沿实际 handler 调用链复用正向能力；缺失组合分别实现请求与响应映射，不能假设反向复用流式转换。核心范围为 messages/tools/stream/usage；不支持字段或能力显式报错。
- **验收**：Chat × 4 outbound 的非流式/流式、工具调用、usage 分别记录结果；不支持项有负例。Cline、Continue 实测只宣称通过的组合。

## 6. Crate 化（D3）与进程模型（D4）

### 6.1 workspace 拆分

```
src-tauri/
  crates/
    phi-gateway/    # proxy/* 整体（handlers、providers、路由、矫正器、usage 采集接口）
    phi-store/      # database/*（schema、迁移、DAO）
    phi-secrets/    # Keychain 封装（07）
    phi-adapters/   # *_config.rs、live/、mode/（04）
    phi-app/        # Tauri 壳：commands、services、托盘、深链、更新（依赖以上四个）
```

拆分规则：`phi-gateway` 与 `phi-store` 之间只通过 trait 接口交互（`UsageSink`、`RouteDecisionSink`、`BudgetGate`、`ProviderRepository`），由 `phi-app` 组装注入。核心完成操作由单一 LedgerCommit 接口提交 attempt、请求投影、预算和汇总，不能让 UsageSink 与 RouteDecisionSink 独立提交而破坏 06 的事务性。trait 定义放在网关侧或中立契约模块，store 实现、app 注入，禁止 gateway/store 双向依赖。适配器通过 SecretResolver 解析凭据，不依赖 Tauri。该拆分便于 headless 运行，但真正分离进程仍需 IPC、生命周期和配置同步设计，不能仅换二进制就视为完成。

### 6.2 进程内运行的自愈

- 沿用 panic="unwind"；supervisor 持有可等待的服务任务句柄，对 listener 任务退出实施有限次数退避重启。重启前取消旧任务并释放端口，单请求任务 panic 只终止该请求。不得重复监听或自动重放已发出的请求。
- 该机制仅覆盖可捕获的 Rust task panic/退出，不覆盖进程 abort、OOM、原生崩溃及 OS kill；在途请求可能失败。进程重启后核对恢复记录，不承诺无损续流。
- 存活状态来自本进程任务句柄、listener 探测和单调时钟心跳；超过 15s 标记异常。持久化的上次运行状态不能证明当前存活。

## 7. 配置与诊断面

- 监听：地址/端口持久化于 `proxy_config` 表（继承），地址受 07 §3.4 的回环限制；phi 增加"一键换端口 + 冲突检测"（对 Agent 配置的联动改写走 04 适配器）；
- 诊断：新增 Tauri command `diagnose_gateway`：自检 listener、出站 TLS（rustls 根证书）、各 provider 端点连通（复用 `speedtest`）、最近 N 条 `log_codes` 汇总；
- 日志：`log_codes` 体系保留并扩展 phi 专属码段（`P*` 前缀），脱敏规则见 07 §4。

## 当前实施补充（2026-10-13）

- 网关随 PHI 启动，和供应商、路由规则及已接入应用数量无关；所有应用退回直连或 Desktop 换走模型映射都不停止监听。退出 PHI 时恢复客户端并停止网关。
- 路由页不提供手动启停。设置页修改端口后重启并同步已接入客户端；绑定失败回退原配置和监听。初次启动端口被占用时显示未就绪，修改端口或“重试启动”可恢复，不显示虚假的运行状态。

- `proxy/supervisor.rs` 持有 listener 子任务；panic/退出/15s 心跳过期后先取消并等待，再按 100/500/1000ms 退避，单次运行最多三次重启。连接任务使用 JoinSet 随 listener 结束取消；不重放请求。
- `ProxyServer::get_status` 结合任务句柄、单调心跳与监督状态，避免把数据库旧状态当作存活证明。端口探测仅诊断时执行；失败后在设置页重试可重新建立监督任务。
- `diagnose_gateway` / `diagnose_adapters` 已接入设置页：本机健康检查、端口、账本、路由发布、近期预算码、配置语法和未完成操作。可选 HEAD 探测最多四并发，不带密钥、不跟随重定向；只证明连接/TLS 能建立，不证明模型调用成功。
- 五 crate 拆分、完整内容加密录制与配置漂移修复仍未交付，状态见 11。

### 通用 Chat 接入的实际覆盖

自定义接入绑定的 `/v1/chat/completions` 经 `proxy/chat_bridge.rs` 显式转换到既有 Responses 链路，当前通过 Anthropic、OpenAI Chat、OpenAI Responses 三种出口。非流式和 SSE 的文本、工具调用、usage 共 12 条完整 HTTP 路径在 `proxy/golden.rs` 回归；含本地认证剥离、实际出口路径/模型、账本用量断言。Gemini 出口仍显式不支持，不能宣称 Chat ×4 全覆盖。

嵌套消息/工具/response_format 严格校验，不能保真的字段在上游调用前拒绝。流式按 output/content index 拼接，最终快照只补未发送后缀；已发送工具身份或文本被改写时明确失败。累计内容限制 16 MiB、单工具参数 2 MiB，并限制槽位数。无终结事件 EOF 为中断。最终 usage 先记账，再做内容转换，客户关闭 include_usage 或转换失败不会抹掉已收到的用量。此批合成用例不等于 120 例能力矩阵、加密录制或真实客户端实测。
