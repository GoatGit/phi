# 08 · 品牌迁移与桌面端设计

> 改造级别：**增强**。基线：React 18 + Vite 7 + shadcn/ui + TanStack Query v5，i18n ×4（zh/zh-TW/en/ja），`whats-new/` 机制，托盘 + 单实例 + 窗口状态 + 开机自启 + 深链 + 更新插件。

## 1. 目标

用户从图标、名称、更新提示到文案，看到的都是 **phi**；同时组件资产、交互惯性（基线 UI 已被验证可用）全部保留。**V1 桌面端不做大改版**，只做品牌替换 + 信息架构轻调 + 差异化页面新增。

## 2. 品牌替换清单（M0，机械但必须清单化）

| 项 | 基线值 | phi 值 |
|---|---|---|
| productName | `CC Switch` | `phi` |
| identifier | `com.ccswitch.desktop` | `ai.phi.desktop`（以最终域名定，原则：自有域名倒写） |
| 深链 scheme | `ccswitch://` | `phi://`（`tauri.conf.json` plugins.deep-link + `deeplink/` 命令） |
| 数据目录 | `~/.cc-switch/` | `~/.phi/`（06 §2 迁移） |
| 更新 endpoint | 上游服务器 | 待确认所有权的 HTTPS 更新域名（示例不得作为正式端点） |
| 图标 | 上游图标 | phi 图标（全尺寸：32/128/128@2x/icns/ico + 托盘） |
| 窗口标题/托盘文案/首启向导 | 上游 | phi |
| i18n 全量文案 | 上游 | 逐键位替换（四语言同步改，CI 加"品牌词残留检查"） |
| `whats-new/` | 上游发布说明 | phi 发布说明机制保留，内容重写 |
| LICENSE / 关于页 | 上游 MIT | 保留上游版权 + `THIRD-PARTY-NOTICES.md`（01 §2.3） |

CI 检查：`grep -ri "cc.?switch\|ccswitch" src/ src-tauri/src/` 白名单机制（LICENSE、迁移向导中提及上游的文案允许），非白名单命中即失败。**更新端点指向必须换**的另一个原因：避免 phi 用户被上游更新器劫持或反之。

## 3. 发布通道

- **签名**：三平台签名密钥自备（macOS Developer ID + 公证、Windows 代码签名、Linux AppImage 签名清单）；Tauri updater 密钥对更换（07 §6）；
- **渠道**：官网下载 + GitHub Releases（fork 仓库）+ 自建更新 JSON（updater endpoint）；**不上架商店**（V1）；
- **打包矩阵**：继承基线 targets（dmg/MSI per-user/AppImage/deb），Windows aarch64 的 rquickjs bindgen 特性保留；
- **发布前置**：核验域名控制权、TLS、签名公钥及从旧版本升级的真实路径；未就绪时关闭更新检查，不请求示例域名。品牌扫描覆盖配置、Cargo/package 元数据、CI、深链注册及更新 JSON，不只扫源码。
- **版本策略**：phi 独立版本号，从 `1.0.0-beta.1` 起（与上游 4.x 彻底脱钩）。

## 4. 信息架构：从"切换器"到"网关控制台"

基线导航以"供应商切换"为中心。phi 的核心叙事是网关，导航轻调为五个一级区（组件全部复用现有资产，V1 不重写视觉体系）：

```
① 模型目录    providers + 端点 + 订阅账号（继承）+ 模型清单（model_fetch）
② 网关与路由   应用连接 · 路由策略 · 路由状态（03/10）
③ 账本        本月报表 · 请求流 · 会话视图 · 预算（05）
④ 配置中心    各 Agent 配置状态 · 版本历史/diff/回滚 · 诊断（04）
⑤ 设置        凭据与安全 · 更新 · 数据目录 · 关于（含上游致谢）
```

路由页只保留“应用连接、路由策略、路由状态”三个标签，复用 shadcn 组件。路由组表单取消允许应用、手动策略选项、成员开关和新增意图规则；成员手柄拖动排序，删除使用图标按钮。应用兼容性自动生成，旧停用成员、手动策略与已有意图规则继续兼容，已有意图规则默认收起。路由策略页仅管理路由组，取消独立匹配规则板块；请求记录与解释合入状态页，共享筛选、统计和刷新。预览与出口运行详情按需展开，减少首屏信息密度。应用连接表合并模式、接入状态和操作，以“直连 / 路由组列表 / 未配置”单一选择控件配合“配置”按钮，选择路由组后该应用的请求统一由该组调度；配置目标显示直连供应商或组内供应商摘要。供应商页的“新建”复用原 AddProviderDialog 完整模板，直接保存独立资源池；不另建删减模板的供应商表单。预算与账单核对已置于用量统计，加密版本历史仍按 04/07 章推进。

供应商页统一使用“新建供应商”及完整模板，不再提供从各应用复制配置的手工“导入供应商”按钮和两步弹窗；空状态与路由缺少供应商时均引导新建。已有资源池供应商、迁移来源及路由引用继续兼容，不因入口移除而删除数据。

共享资源池的新建页不再显示应用选择框。原各应用的供应商模板合并为可搜索的列表，同名、同套餐及同地区模板仅保留一份，优先沿用现有资源池默认模板；套餐和地区差异继续保留。选中后自动加载对应完整表单，仅写入资源池；应用使用哪个供应商由后续连接和路由配置决定。

应用连接展示完整的 10 个受管应用，不再把 `PROXY_APP_IDS` 的 4 个应用误当作总清单。Claude Code / Codex / Gemini / Grok 通过连接方式选择框切换直连与兼容路由组；Claude Desktop 读取独立配置状态，进入其配置页管理。OpenCode / OpenClaw / Hermes / Pi / MiniMax Code 读取实际已写入配置的供应商，标注“应用内选择”，通过配置入口管理，不把仅保存在目录中的供应商当作生效目标，也不套用尚未实现的统一接管开关。读取失败保留对应应用行并提供重试。

所有应用行的“配置”按钮统一打开对应应用的供应商设置页，不因直连、代理或接入资源池而改变跳转目标；路由组通过“路由策略”标签管理，匹配规则配置已移除。

应用供应商设置页顶部不再放置“添加供应商”按钮，减少页头操作。共享供应商页继续通过“新建供应商”进入完整模板列表。

### 4.1 关键新增交互

- **首次启动向导**（新建）：检测旧数据并完成安全迁移（06 §2）→ 验证原生 baseline/处理已接管状态（04 §2.1）→ 创建接入身份与项目绑定 → 选择主力 Agent → 引导写入 → 网关连通自检（`diagnose_gateway`）；
- **请求三元组卡片**（05/03）：请求详情页顶部"模型 · 费用 · 为什么选它"，是差异化体验的锚点交互；
- **紧急恢复入口**（04 §2.2）：托盘常驻。

### 4.2 状态可见性

- 网关随 PHI 常驻运行，不设全局启停开关。路由页仅保留标题中的网关状态和读取失败反馈；移除连接引导说明、监听地址、常驻提示和“网关设置”按钮，端口继续在设置页修改。应用接入开关只管理客户端配置，不影响共享网关。启动失败显示未就绪，设置页保留恢复用的重试入口。

内置应用连接继续自动管理本地认证；移除路由页“高级：其他客户端接入”区块，不再要求用户手工管理令牌。已有认证和数据保持兼容，信任边界见 07 §3.4。预算页不再引导到已删除的项目登记入口。

- 主窗口常显：网关状态（存活/端口）、当前各工具生效 provider、今日费用摘要；
- 异常冒泡：熔断触发、预算 warn/block、Agent 配置被外部修改——四语言文案。

### 4.3 菜单栏面板（2026-10-13 实施补充）

macOS 菜单栏和 Windows 托盘左键、右键均打开同一个紧凑面板，参照 magpie 的圆角浅灰面板、白色选中标签、可折叠 Agent 卡片及底部操作栏。面板为独立窗口，默认 440 × 520 逻辑像素，随主窗口主题变化；按托盘位置和当前屏幕工作区定位。两种按键均在释放时响应一次；再次点击、点击窗口外或按 Escape 收起，下拉菜单打开时 Escape 先关闭下拉菜单。

| 区域 | 当前行为 |
|---|---|
| 顶部 | PHI 标识、刷新、打开主窗口、设置 |
| Agent | 遵循设置里的应用可见性；默认展开首个已接入应用，其余可展开。显示接入开关、供应商选择和模型摘要；模型行打开对应应用页管理模型 |
| 额度 | 展示原托盘已有的缓存额度及重置时间，刷新复用额度查询。无数据与查询失败分别提示 |
| 用量 | 本地自然日的已记录请求、Tokens、已知估算费用和成功率；可打开完整用量页。原生直连未采集数据不计入 |
| 路由 | 读取既有路由数据接口，显示最近 24 小时请求、活跃请求、故障转移次数、P95 和最近五条记录；可打开路由页 |
| 底部 | 已有方案选择、打开 PHI、退出；退出沿用应用原有的停止路由与恢复配置流程 |

供应商和方案切换沿用现有后端操作，并在执行时重新检查选项可用性。等待操作完成后刷新状态；失败显示错误，不能提前显示切换成功。需要重新打开 Agent 才能生效的切换保留现有提示。接入开关关闭时恢复该应用的原生直连配置。

面板显示期间每 3 秒刷新状态，路由标签每 3 秒刷新，用量标签每 15 秒刷新；隐藏后暂停轮询，再次打开时刷新。快照仅含显示字段，不传递供应商凭据或完整配置。

macOS/Windows 不再挂载原生托盘菜单；设置更新、供应商切换和故障转移只刷新托盘状态，不得重新挂回旧菜单。两键共用面板的定位与失焦处理。Linux 的 AppIndicator 不提供图标点击事件，暂保留原生菜单兼容入口，不能宣称具有相同的左右键行为。实施文件为 `src/components/tray/TrayPanel.tsx`、`src/tray.tsx`、`src-tauri/src/tray/panel.rs` 与 `src-tauri/src/tray.rs`。

### 4.4 主窗口可达性（2026-10-13 修正）

主窗口移动、调整尺寸、缩放变化，以及启动或从 Dock、托盘、深链和轻量模式恢复时，检查顶部是否仍有可用拖动区域。仅窗口内容或操作按钮露在屏幕内不算可拖回。拖动区域不可达时，将窗口移入最近的显示器工作区；使用物理坐标，支持负坐标显示器、上下排列、多屏不同缩放及菜单栏/任务栏占用。macOS 直接读取 `NSScreen.visibleFrame`，统一换算到当前窗口的缩放比例，避免不同显示器的坐标直接比较，并正确避开顶部菜单栏。

检查合并到移动停止后的 250ms；macOS 鼠标尚未松开时继续等待，避免拖动中抢位置。正常跨屏、部分超出屏幕但仍可拖动的窗口保留原位置；全屏、最大化、最小化及隐藏窗口不调整，不改变窗口尺寸。菜单栏面板继续使用自己的锚点定位。系统不提供窗口位置时（例如部分 Wayland 合成器），遵循系统窗口管理策略。

实现：`src-tauri/src/window_bounds.rs`。`cargo test --release --lib window_bounds::` 的 14 项测试通过，覆盖四边越界、标题栏不可达、显示器断开、负坐标、混合缩放、工作区和重复回收；原生鼠标拖动及跨屏行为仍需桌面端实测。

### 4.5 长表单与保存状态（2026-10-13 修正）

供应商编辑、路由组、手工接入、预算和账单表单统一采用固定标题、正文滚动、固定底部操作。使用 `DialogBody` 承担滚动，外层弹窗限制在可用视口内；不能让长模型清单、组成员或意图规则把取消和保存按钮挤出窗口。900 × 600 逻辑像素作为小窗口回归尺寸。

保存期间禁止重复提交、取消和 Escape 关闭，禁用草稿控件；Radix 下拉框显式传入禁用状态，不能只依赖原生 fieldset。失败保留输入并恢复编辑，校验/保存错误在正文滚动区域之外显示，以便滚到表单底部时仍能看到。目录 revision 变化时，路由组保留草稿并提示重新核对，禁止旧草稿覆盖新目录。

预算和账单的金额保持字符串输入，不在编辑时转为浮点数；提交前检查非负 Decimal 可精确表示的范围。Token 上限保留原始文本，提交时验证非负安全整数。账单日期允许清空，校验通过后才转为 UTC 零点；结束日期排除在外，须晚于开始日期且周期不超过 366 天。删除账单须确认，失败保留记录并允许重试。

### 4.6 路由状态流转图（2026-10-13 补充）

参考 magpie `internal/gui/assets/routing.js` 与 `routing.css`，在路由状态页的统计摘要下展示“应用 → PHI → 供应商 / 模型”流转图。供应商节点保留嵌套路由组路径，区分调用中、已完成、失败、冷却、跳过和未尝试；线条和文字共同表达状态，不能只靠颜色。失败尝试与后续成功出口同时保留，便于看清故障切换。

图表复用状态页每 5 秒刷新的筛选结果，默认跟随最新进行中的请求，无进行中请求时展示当前页最新记录；可以切换到具体请求。选路策略、名称、路径、意图分类和会话保持均使用请求当时的快照；不读取当前目录重算历史。上游接受请求不等于完成，最终成功或流式中断以请求结局为准。当前无记录时显示等待请求，不生成模拟流量。

支持按真实尝试顺序回放、暂停，以及点击某次尝试查看当时路径；回放按固定节奏逐项呈现，不模拟真实耗时。进行中的请求和用户主动回放使用流动虚线，静态历史不持续动画，遵循系统减少动态效果设置。窄窗口只在图内横向滚动，不撑宽页面。详细出口运行指标和历史解释表继续保留。

### 4.7 应用内终端标签（2026-10-14 首版已接入）

支持 CLI 的应用页顶部增加固定“配置”标签、可关闭的终端标签和 ＋。点击 ＋ 直接在嵌入终端启动当前应用 CLI；切换配置、应用或全局页面时保留进程。工作目录沿用当前终端的启动目录 / 应用上次目录，另提供“在其他目录新建”。Claude Desktop 不显示终端入口，首版嵌入平台为 macOS。

采用原生 libghostty 视图，生命周期与 React 页面挂载分离；关闭运行标签需要确认，最小化到托盘保持运行，真正退出汇总确认后清理会话。顶部 ＋ 不用于添加供应商。交互、启动命令、原生视图层级和实施验收见 [12-嵌入终端与应用标签页设计](12-嵌入终端与应用标签页设计.md)，并提供[可点击原型](../design/embedded-terminal-tabs.html)。macOS 13+ 已接入真实 Ghostty；支持范围与实测限制见 12 §7.4。
