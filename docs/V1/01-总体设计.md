# 01 · phi V1 总体设计

> Fork 基线：cc-switch v4.0.8（`tmp/cc-switch`，git `2b0ec81`）。本文是 V1 全部设计的总纲。

---

## 1. 产品定位与核心体验

### 1.1 定位

phi 是本地优先的 AI Agent 网关：向上接管主流 Agent 的模型请求，向下编排多个模型供应商、账号与订阅，在中间完成协议转换、路由与故障转移、配置管理、成本归因。

### 1.2 核心体验：让用户自由使用所有模型

按产品前提，核心体验与延伸体验分层如下，V1 的范围划分、验收标准、商业化叙事均以此为纲：

| # | 自由要素 | 含义 | V1 来源 |
|---|---|---|---|
| 1 | 接入自由 | 任意 Agent 能指向 phi | **继承**：10 个 Agent 的 live 配置读写 + 网关接管 |
| 2 | 模型自由 | 完整模型目录：官方 API、聚合商、订阅、本地 | **继承为主**：Anthropic/OpenAI(Chat+Responses)/Gemini/Copilot/xAI 适配；缺口见 02 |
| 3 | 凭据自由 | API Key 与订阅 OAuth 都能用 | **继承**：key、OAuth（Codex/Claude/Copilot/xAI）；**升级**：Keychain 存储 |
| 4 | 切换自由 | 切换摩擦趋近零、Agent 无感知 | **继承**：一键切换、热切换、Profile |
| 5 | 连续性 | 资源断了自动续上 | **继承**：故障转移队列 + 熔断 + 健康监控；**增强**：决策可解释 |
| 6 | 反锁定 | 随时可回到无 phi 状态 | **继承并强化**：原生配置备份、一键恢复、配置版本化 |

延伸体验（V1 做但不是获客主张）：请求级账本与归因、预算告警与已结算阈值拦截、路由解释、会话观测。

### 1.3 价值主张（对外一句话）

> phi：让任意 Agent 自由使用任意模型——本地网关，一次接入，全模型可用；钱花在哪、路由为什么、出了事怎么办，都有账可查。

获客靠前半句（核心体验），付费转化靠后半句（延伸体验）。

## 2. Fork 策略

### 2.1 基线冻结

- **当前基线**：以 FORK-BASELINE.md 记录的 main 快照 2b0ec81 为准，代码版本标识为 v4.0.8；尚不能据此宣称它等同于 release tag 或最新稳定版。M0 发布冻结须记录完整 commit、选定 tag 及差异；若切换到其他提交，重新跑兼容测试并更新全部基线引用。
- **冻结后仓库操作**：导入上游代码为 phi 仓库初始提交（保留完整 LICENSE 与版权声明），此后 `main` 与上游无 merge 关系。
- **不合并 ≠ 不看上游**：建立"上游差watch"流程（见 04 §5），对 `*_config.rs`、`proxy/providers/`、`proxy/usage/`、安全修复类 commit 做**手动移植评估**。移植决策记录在 `docs/upstream-porting-log.md`。

### 2.2 为什么 fork（继承能力盘点）

| 能力 | 基线状态 | 自建等价成本估计 |
|---|---|---|
| 10 个 Agent 配置读写（switch/coexist 双模式、原子写） | 已验证，含边界处理（注释保留、格式保留） | 3–5 人月，且持续追格式变化 |
| 协议互转引擎（5 类供应商适配 + 4 组跨协议 transform/streaming + thinking 矫正器） | 经真实流量打磨 | 6–12 人月，是协议兼容性风险的主要来源 |
| 熔断、故障转移队列、健康监控 | 已实现（circuit_breaker/failover_switch/provider_health） | 1–2 人月 |
| 请求级 usage（解析/计价/落库 + 日汇总 + 会话级解析） | 已实现（proxy/usage + 6 个 session_usage_* 服务） | 2–3 人月 |
| 桌面基建（打包矩阵、更新、托盘、i18n×4、单实例、深链） | 已验证 | 1–2 人月 |
| 测试基建（vitest+MSW、cargo test、三平台 CI） | 已建 | 1 人月 |

结论：fork 节省约 **14–25 人月**，并把 phi 最大的技术风险（协议兼容）转移到一个已被市场验证的代码库上。

### 2.3 法律与品牌义务（MIT）

1. 在产品"关于"页与发行物中保留上游 LICENSE 文本与版权声明（`MIT © Jason Young`），建立 `THIRD-PARTY-NOTICES.md`；
2. 不使用 "CC Switch"、"ccswitch" 名称、logo 与官网域名；deep-link scheme、bundle identifier、更新服务器全部更换（见 08）；
3. 允许闭源商用；对上游保持善意：对外承认 fork 来源，条件允许时回馈零星修复（非义务）。

## 3. V1 目标与非目标

### 3.1 目标（按优先级）

| # | 目标 | 说明 | 对应设计 |
|---|---|---|---|
| G1 | 品牌化独立交付 | 改名、改标识、自建更新通道，产物是"phi"而不是"cc-switch 改" | 08 |
| G2 | 凭据安全升级 | API Key 从 SQLite 明文迁移到系统 Keychain；安全审计项清零 | 07 |
| G3 | 账本归因 V1 | 请求级账本增加项目/Agent/会话归因维度与报表，预算告警 + 已结算阈值拦截（非严格金额上限） | 05, 06 |
| G4 | 路由组与可解释路由 V1 | 组内策略、嵌套、会话保持和可选意图分类；实际路径与决策快照在控制台可查，当前存 gateway_traces | 03, 06, 10 |
| G5 | 配置版本化与一键恢复 | 验证原生 baseline、加密历史、三方恢复与冲突处理 | 04 |
| G6 | 协议黄金集回归 | 录制真实请求/响应对，形成跨协议转换的回归防线 | 02, 09 |
| G7 | 协议缺口补齐 | 已有 Chat 入口的通用工具接入完善 | 02 |

### 3.2 非目标（V1 明确不做）

- **CLI**：继承桌面端能力已够验证期使用；CLI 列入 V1.x；
- **独立网关进程**：V1 完成网关代码 crate 化与接口隔离（为进程分离铺路），进程分离本身列 V1.x；
- **学习型路由 / 质量路由**：不自动学习任务质量；意图路由已按 2026-10-13 用户确认纳入 V1，采用显式分类模型与有序规则，见 03/10；
- **团队协作、SSO、私有部署**；
- **跨设备同步作为卖点**：WebDAV/S3 仅保留非敏感配置同步，改用允许清单与目标设备凭据重绑（07）；不进营销叙事；
- **MCP/Skills/Prompt 管理增强**：继承现状，仅做品牌化文案；
- **订阅账号共享/转售**：继承的订阅 OAuth 能力保留（属"凭据自由"），但仅限用户本人账号，见 07 §5。

## 4. 总体架构

### 4.1 继承架构（基线现状）

```
Frontend（React 18 + TS，src/）
  components/* ── hooks ── TanStack Query ── lib/api（invoke 封装）
                          │ Tauri IPC
Backend（Tauri 2 + Rust，src-tauri/src/）
  commands/*（薄命令层，按域拆分 ~35 个文件）
      └► services/*（业务逻辑：provider/mcp/skill/prompt/profile/proxy/
                    usage_stats/session_usage_*/model_pricing/subscription/s3/webdav…）
            ├► database/（schema.rs 建表与迁移、dao/*、backup.rs）
            ├► live 配置写入：*_config.rs + live/ + mode/（switch|coexist，原子写）
            └► proxy/（进程内 axum 网关：providers 适配、transform/streaming、
                       circuit_breaker、failover_switch、provider_router、
                       thinking 矫正器、usage 统计、session 提取）
```

- **SSOT**：`~/.cc-switch/cc-switch.db`（phi 改为 `~/.phi/phi.db`）；设备级设置在 `settings.json`；
- **网关进程模型**：与桌面 UI 同进程（tokio 多线程 runtime 内启动 TcpListener）；
- **请求路径**：Agent → 本地 axum → provider_router（选 provider）→ 适配器转换 → 上游 → response_processor/usage → 回写 Agent。

### 4.2 改造架构（phi V1 目标）

```
┌─ 桌面壳（Tauri 2，品牌化）──────────────────────────────┐
│  控制台 UI：模型目录 · 路由策略 · 账本报表 · 配置管理 · 设置 │
└──────────────┬───────────────────────────────────┘
               │ Tauri IPC
┌──────────────┴──────────── backend crates ──────────────┐
│ phi-gateway（02/03）：axum 网关、协议适配、路由决策、      │
│   熔断/故障转移、决策日志、usage 采集                     │
│ phi-store（06）：SQLite schema+迁移+DAO、账本归因、       │
│   预算/限流、配置版本化                                   │
│ phi-secrets（07）：Keychain 封装、密钥迁移                │
│ phi-adapters（04）：10 Agent live 配置读写、版本化、恢复   │
│ phi-app（壳层粘合）：commands、services、托盘、深链、更新  │
└───────────────────────────────────────────────┘
```

改造级别定义：**继承**（原样保留，仅品牌化）／**增强**（保留结构，扩展字段或行为）／**重构**（结构调整，行为兼容）／**新建**。

| cc-switch 模块 | phi 归属 | 级别 | 说明 |
|---|---|---|---|
| `proxy/server.rs` `handlers.rs` | phi-gateway | 增强 | 统一鉴权、监听限制、可解释日志挂钩（CSP 属桌面壳） |
| `proxy/providers/*` `transform_*` `streaming_*` | phi-gateway | 继承+黄金集 | 不动逻辑，补回归测试 |
| `proxy/{circuit_breaker,failover_switch,provider_router}.rs` | phi-gateway | 增强 | 接入决策日志与预算检查 |
| `proxy/usage/*` `services/usage_stats.rs` | phi-gateway/phi-store | 增强 | 归因字段、预算联动 |
| `proxy/{thinking,opaque_state,media}_*.rs` 矫正器 | phi-gateway | 继承 | 上游差异化处理的经验结晶，原样保留 |
| `*_config.rs` `live/` `mode/` | phi-adapters | 增强 | 配置版本化与恢复 |
| `database/*` | phi-store | 增强 | 新表迁移（06） |
| `commands/*` `services/*`（非上述） | phi-app | 继承 | 品牌化与裁剪 |
| `deeplink/` `session_manager/` `mcp/` `pi_config/` | phi-app | 继承 | scheme 改 phi:// |
| `src/`（React） | 桌面壳 | 增强 | 信息架构调整（08） |

### 4.3 关键决策记录（ADR）

| # | 决策 | 理由 | 代价与缓解 |
|---|---|---|---|
| D1 | fork v4.0.8 后**不合并上游** | 消除合并负担；基线已覆盖核心体验大半 | 适配器漂移 → 04 §5 上游追踪 SOP 手动移植 |
| D2 | 凭据迁入 Keychain/口令保险库，结构化数据存引用、快照加密 | 覆盖整个持久化生命周期 | 失败停在向导，不激活明文库；同步重绑，完整备份加密 |
| D3 | 后端拆分为 **5 个 crate**（workspace 化） | 为网关独立进程与可测试性铺路 | 一次性重构成本，M0 内完成 |
| D4 | V1 网关**保持进程内**，不做独立守护进程 | 进程分离收益不抵 V1 复杂度；crate 化已隔离风险 | supervisor 仅恢复可捕获的任务退出；进程崩溃及在途请求损失仍存在，不能承诺无损恢复 |
| D5 | **保留订阅 OAuth 能力**（Codex/Claude/Copilot/xAI），UI 透明声明 | 凭据自由是核心体验；共享/转售仍禁止 | 合规争议 → 07 §5 声明与风险提示 |
| D6 | 复用请求级投影，新增逐尝试权威账本 | 保留兼容性并计入重试成本 | 同事务更新预算与汇总，避免重复计费 |
| D7 | 路由 V1 = 路由组 + 可解释策略 + 可选意图分类；不做学习型路由 | 用户控制分类出口、规则与回退 | 分类增加延迟和费用 → 有界调用、明确数据去向、独立记录开销 |
| D8 | 协议正确性靠**黄金集回归**保障而非重写 | fork 最大风险是"改坏看不见的兼容性" | 需要真实流量录制工具（02 §4） |

V1 预算采用已结算阈值拦截：达到阈值拒绝后续尝试；在途请求可能超支。严格金额硬上限不属于当前实现承诺，见 05 §3。接入身份来自认证绑定，不能从协议入口或事后扫描推导在线预算权限。

### 4.4 技术栈

继承基线全部技术栈（见 README 速览）。新增：

- `keyring` crate（系统凭据存储，macOS Keychain / Windows Credential Manager / Linux Secret Service）；
- `cargo workspace`（crate 拆分）；
- 黄金集工具链：独立加密录制挂钩（不依赖请求日志具有正文）+ 快照断言（serde_json 规范化后 diff）。

## 5. 里程碑与验收

### M0 · 接管（第 1–2 周）

基线记录核对 → 先建立至少 30 例合成黄金集 → 仓库 workspace 化（D3）→ 品牌机械替换（08 §2 清单）→ 三平台构建 + 签名 + 更新通道跑通 → 全量测试绿（`pnpm typecheck && pnpm test:unit` + `cargo fmt/clippy/test`）。

**出口标准**：产物为 phi dev build；上游代码 100% 测试通过；`grep -ri "cc.switch\|ccswitch" src/ src-tauri/src/` 结果可控（允许 LICENSE/注释类残留，功能面清零）。

### M1 · 安全与差异化地基（第 3–6 周）

Keychain 迁移（D2）→ 新表迁移与账本归因（G3/G4，06）→ 配置版本化与一键恢复强化（G5）→ 决策日志落库 → 首次启动向导（备份原生配置 → 引导接入）。

**出口标准**：新库/老库（v4.0.8 库升级）迁移测试通过；phi 管理存储凭据明文清零（live/旧目录边界见 07）；一次请求可在 UI 看到"模型、费用、路由原因"三元组。

### M2 · 验证版（第 7–10 周）

协议黄金集建成并全绿（G6）→ 通用 Chat 接入完善（G7）→ 报表与预算限流打磨 → i18n 文案翻新 → 用户文档。

**出口标准**：达到 09 §3 CI 门槛与 §4 产品验收清单；发放 10–20 名重度 AI 开发者两周验证。

### M3 · GA 决策

按验证数据（网关留存、故障转移使用率、账本查看频率、付费意愿）决定 GA 或回调范围。GA 前必须完成：更新通道灰度、崩溃上报（本地优先：默认关闭、显式开启）、法务审查（07 §5）。

## 6. 风险登记

| 风险 | 等级 | 影响 | 对策 |
|---|---|---|---|
| 上游迭代导致 Agent 配置适配器漂移 | 高 | 切换成功率下降 | 04 §5 上游差watch + 手动移植 SOP + 切换成功率监控 |
| fork 改动破坏隐式协议兼容（无测试覆盖的边界） | 高 | 流式/工具调用静默劣化 | G6 黄金集回归为 M2 硬门槛；改动 providers/ 前先补录制 |
| proxy 与 UI 同进程的单点故障 | 中 | UI 崩溃连带断网关 | D4：受限的任务监督重启；进程崩溃仍中断请求，V1.x 再隔离进程 |
| SQLite 明文密钥残留 | 中 | 凭据泄露 | G2 Keychain 迁移 + 审计脚本 + 迁移测试 |
| 订阅 OAuth 的供应商条款风险 | 中 | 账号风控、舆论 | D5：仅本人账号 + UI 声明 + 法务审查；不做共享/转售 |
| 品牌替换不彻底（更新撞源、深链冲突、残留遥测） | 中 | 用户混淆、合规 | 08 §2 清单化 + CI 检查项 |
| 范围膨胀（重蹈 V0 覆盖面过大） | 中 | 交付延期 | 3.2 非目标清单为硬约束，新增范围必须走 ADR |
| 上游 License 变更影响（现 MIT） | 低 | 合规 | 冻结版本即锁定 MIT；上游后续变更不影响已 fork 代码 |
