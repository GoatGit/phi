PHI を作った理由

ツールが増えるほど、設定は散らばっていく。

Claude Code、Codex、Gemini CLI を同時に使っているかもしれません。それぞれ違うプロトコルで話し、設定も別々に持っています。プロバイダーを変えるには三、四か所を直し、ルートを変えるには前回どのファイルを触ったかを思い出す必要があります。

PHI はこれらを同じウィンドウにまとめます。プロトコルはゲートウェイで変換し、回線はルートグループが割り当て、ターミナルも同じアプリの中にあります。プロバイダーは一度設定すれば、複数のツールで使えます。PHI アカウントは不要で、設定と統計はこのマシンに残ります。モデルの利用には、ご自身のアカウントまたは API キーを使います。

開発の出発点は CC Switch 。独立したフォークとして、Tauri 2、Rust、React で開発しています。

01ゲートウェイの統合

4 つは利用可能。5 つ目は近日対応。

Claude Code は Anthropic Messages、Codex は OpenAI Responses、Gemini CLI は Gemini ネイティブで話します。接続先のプロバイダーは別のプロトコルでもかまいません。PHI が判別し、そのまま通すか変換するので、ツールごとにプロバイダーへ接続し直す必要はありません。5 つ目は System One。質問と回答で構成される判断プロトコルで、近日対応予定です。

OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini ネイティブ。入口側と上流側でそれぞれ選べ、同じである必要はありません。
System One（近日対応）
判断プロトコルです。リクエストには状態と複数の質問が含まれ、応答は確率付きの構造化された回答になります。ゲートウェイ内でも独自の経路を通り、チャットリクエストとして書き換えられることはありません。
同一プロトコルの透過転送
両側が同じプロトコルなら、そのまま転送します。ストリーミング、ツール呼び出し、使用量のフィールドは書き換えません。
プロトコル間の変換
リクエスト、レスポンス、ストリーミングイベントを対象プロトコルへ変換します。ツール呼び出し、思考内容、トークン使用量はできるだけ保持します。

System One はまだ利用できません。公開後はプロバイダーのプロトコル一覧に表示されます。プロトコルをまたぐ接続では、まず簡単なタスクでツール呼び出しとストリーミングを確認してください。Gemini CLI は現在、Gemini ネイティブの上流のみを受け付けます。

02ルートの統合

  • セッション親和性

    同じ会話はできるだけ同じメンバーに留まり、文脈を往復させずに済みます。

  • フェイルオーバー

    条件に合うエラーでは次の回線へ切り替えます。失敗が続くメンバーは一時的に冷却し、回復後に戻ります。

03セッションと記憶の統合計画中

セッションは、ツールを変えても引っ越さない。

PHI は各ツールがこのマシンに残したセッション記録を、ひとつの一覧にまとめています。プロジェクト別にまとめ、検索し、元の記録を開き、再開コマンドをコピーできます。次はツールをまたぐ文脈と長期記憶です。このプロジェクトで話したことを、毎回ゼロから言い直さずに済むようにします。

現在

  • 各ツールのセッションを、ひとつの一覧で

    PHI は Claude Code、Codex、Gemini CLI などがこのマシンに残した記録を読み、プロジェクト別または時系列でまとめます。

  • 探せて、戻れる

    タイトル、ディレクトリ、メッセージ、セッション ID を検索。元の記録を開き、再開コマンドをコピーして、そのときの作業ディレクトリに戻れます。

計画中

  • ツールをまたぐ継続セッション

    Claude Code で始めた作業を、Codex でそのまま続けられます。

  • プロジェクトに沿う長期記憶

    好み、決定、プロジェクトの事実を保存し、確認・編集・削除できるようにしたうえで、次のセッションに引き継ぎます。

ツールをまたぐ文脈と長期記憶は計画中です。現在のセッション閲覧は、各ツールがこのマシンに保存した記録を読むだけです。

04CLI ターミナルの統合

モデルを整えたら、あとはターミナルで使うだけ。

アプリページ右上の「＋」をクリックするか、 ⌘Tを押してディレクトリを選べば起動します。まず CLI がインストールされているか確認します。Claude Code、Codex、Gemini CLI など 9 つのツールをこの方法で開け、設定済みのプロバイダーとルートグループも反映されます。 現在は macOS 13 以降のみ対応。CLI が見つからない場合は、インストール案内を表示します。

  • 設定もターミナルも、タブで切り替え

    同じアプリ内で切り替えられます。プロバイダーを変更したら、別ウィンドウを開かずにコマンドを実行できます。

  • 見比べたいときは、画面を分割

    同じツールの 2 つのセッションを並べて、一方で編集し、もう一方で結果を確認。上下分割もできます。

  • いつもの配色で作業

    PHI のライト／ダークに合わせるか、内蔵の配色から選べます。

  • 別のページを見ていても、実行は継続

    別のページで利用状況や設定を確認しても、プロセスは止まりません。

  • CLI を終了しても、シェルはそのまま

    同じシェルに戻るので、作業ディレクトリも直前の出力もそのままです。

05設定

設定は一度書けば、ゲートウェイ、ルート、ターミナルが同じ設定を読みます。

プロバイダー、MCP、Skills、プロンプトをひとつの場所で管理し、各ツールが対応する形で設定に反映します。ゲートウェイ、ルートグループ、ターミナルの CLI は同じ内容を読みます。

プロバイダーとキー
複数のプロバイダーとモデルをまとめ、クリックひとつで切り替え。サブスクリプションの認証情報はシステムのキーチェーンに預けます。
MCP と Skills
サーバーとスキルを一覧で管理。どのツールに導入したか、有効になっているかを確認できます。
プロンプト
よく使うプロンプトをライブラリに保存し、いつでもコピーしたり、プロジェクト設定に書き込んだりできます。
プロジェクトのスナップショット
現在のプロバイダー、MCP、Skills、メモリーファイルをプロジェクトとして保存し、仕事用と個人用の環境をワンクリックで切り替えられます。
アカウントと認証
再ログインが必要なアカウントやデフォルトアカウントを、ひとつの場所で管理します。

06利用状況

今月、何にどれだけ使ったか。

リクエストはローカルゲートウェイを通り、セッション数、トークン、費用、キャッシュヒット、稼働時間がローカルの台帳に記録されます。日ごとの推移や、曜日 × 時間のヒートマップで、よく使う時間帯を見つけられます。

  • アプリ、プロバイダー、モデル別に確認

    合計額だけでなく、どのツールやモデルに費用がかかったかを確認できます。

  • リクエストごとに確認

    各リクエストのモデル、所要時間、トークン、費用を記録します。どの回線が選ばれたかも判断トレースで確認できます。

  • 長いセッションも、状況を把握

    コンテキスト使用量のグラフと自動圧縮のしきい値を見ながら、新しいセッションに移るタイミングを判断できます。

07ローカルデータ

データの保存先を、わかりやすく。

PHI は開発元のクラウドバックエンドを持ちません。設定、セッション統計、利用台帳はローカルの ~/.phi/ に保存し、サブスクリプションの OAuth トークンはシステムのキーチェーンに預けます。オンラインモデルを使うときだけ、CLI またはローカルゲートウェイが選択したプロバイダーへ接続します。

08はじめに

使い慣れたツールから、始めよう。

最初からすべて設定する必要はありません。まずひとつのツールを接続して、少しずつ自分の作業環境を整えていきましょう。

  1. 1

    PHI と使いたい CLI をインストール

    PHI はツールの管理と起動を担当します。CLI は各ツールの公式手順でインストールしてください。すでに入っているものはそのまま使えます。

  2. 2

    プロバイダーと接続方法を設定

    モデルサービスを入力し、「ルート」ページで直接接続かルートグループかを選びます。必要ならグループの戦略も選びます。

  3. 3

    プロジェクトを開いて、作業開始

    アプリページの「＋」からディレクトリを選ぶと、macOS 13 以降ではその場でターミナルが開きます。いつものターミナルでプロジェクトを開いてもかまいません。

よくある質問

ダウンロードの前に。

モデルや無料利用枠は付いていますか？

PHI はオープンソースのデスクトップツールで、モデルの利用枠は提供しません。プロバイダーの API キー、または使うツールが対応するサブスクリプションアカウントを用意してください。モデルの利用料は選択したサービスから請求されます。

直接接続とルートグループは何が違いますか？

直接接続はゲートウェイを通らず、アプリ従来の方法でひとつのプロバイダーにつなぎます。ルートグループは複数のプロバイダーやモデルをまとめ、PHI が戦略に従って選び、失敗時は次へ切り替えます。メンバーは別プロトコルでもかまいません。

キーやリクエストはどこに送られますか？

主な設定と使用量データはこのマシンに保存し、サブスクリプションの OAuth トークンはシステムキーチェーンに預けます。ローカルゲートウェイ経由では、リクエストはまず PHI に届き、設定したプロバイダーへ転送されます。直接接続ではアプリがプロバイダーに直接つなぎます。どちらも、リクエスト内容と必要な認証情報は選んだプロバイダーに渡ります。

セッション統合と長期記憶は今使えますか？

セッション閲覧は利用できます。各ツールがこのマシンに残した記録がひとつの一覧に集まり、プロジェクト別または時系列で表示し、検索し、再開コマンドをコピーできます。ツールをまたぐ継続セッションと長期記憶は計画中です。

Windows や Linux でもアプリ内で CLI を実行できますか？

内蔵ターミナルは現在 macOS 13 以降のみ対応しています。Windows と Linux では、PHI で設定管理、モデル接続、利用状況の確認を行い、CLI は外部ターミナルで実行してください。

更新や不具合の報告はどうすればよいですか？

アプリ内の「更新を確認」、または GitHub Releases から新しいバージョンを入手できます。不具合は GitHub Issues へ、OS のバージョン、ツール名、再現手順を添えて報告してください。キーなどの秘密情報は必ず伏せてください。
