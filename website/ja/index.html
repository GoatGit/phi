PHI を作った理由

設定のために、
こんなに手間をかけなくても。

Claude Code、Codex、Gemini CLI を使い分けていると、それぞれに設定が必要です。プロバイダーを変えるたびに何か所も編集し、モデルを変える前に、前回どのファイルを触ったか探すことになります。

PHI は設定をひとつにまとめます。プロバイダーを一度登録して複数のツールで使い、アプリを離れずにコマンドを実行。PHI のアカウント登録は不要です。設定と統計はローカルに保存し、モデルサービスには自分のアカウントや API キーを使います。

開発の出発点は CC Switch 。独立したフォークとして、Tauri 2、Rust、React で開発しています。

01内蔵ターミナル

PHI の中で、そのまま CLI を実行。

アプリページ右上の「＋」をクリックするか、 ⌘Tを押してディレクトリを選ぶだけ。PHI がインストール済みの CLI を確認し、その場所で起動します。Claude Code、Codex、Gemini CLI など、9 種類のツールに対応しています。 現在は macOS 13 以降のみ対応。CLI が見つからない場合は、インストール案内を表示します。

  • 設定もターミナルも、タブで切り替え

    同じアプリ内で行き来できます。プロバイダーを変更したら、別のウィンドウを開かずにコマンドを実行。

  • 見比べたいときは、画面を分割

    同じツールのセッションを並べて、一方でコードを編集し、もう一方で結果を確認。上下分割もできます。

  • いつもの配色で作業

    PHI のライト／ダークテーマに合わせることも、内蔵の配色から選ぶこともできます。アプリページを切り替えても設定はそのまま。

  • 別のページを見ていても、実行は継続

    別のページで利用状況や設定を確認しても、プロセスは止まりません。戻ったら、そのまま入力を続けられます。

  • CLI を終了しても、シェルはそのまま

    同じシェルに戻るので、作業ディレクトリも直前の出力も残っています。

02ローカルゲートウェイ

ひとつのモデルを、いろいろなツールで。

PHI はパソコン上でゲートウェイを動かします。Claude Code と Codex ではプロトコルが異なりますが、対応する変換をゲートウェイが担当。同じプロバイダーやモデルを、ツールごとに接続し直す手間を減らせます。

設定はローカルに保存されます。モデル利用時は、リクエスト内容と必要な認証情報を選択したプロバイダーに送信します。PHI 自体はモデルサービスを提供しません。

03設定

一度まとめた設定を、各ツールへ。

プロバイダー、MCP、Skills、プロンプトをまとめて管理し、各ツールが対応する方法で設定に反映します。

プロバイダーとキー
複数のプロバイダーとモデルをまとめて、クリックで切り替え。サブスクリプションのログイン認証情報はシステムのキーチェーンに保存します。
MCP と Skills
サーバーとスキルを一覧で管理。どのツールに導入したか、有効になっているかを確認できます。
プロンプト
よく使うプロンプトをライブラリに保存。必要なときにコピーしたり、プロジェクト設定に書き込んだりできます。
プロジェクトのスナップショット
プロバイダー、MCP、Skills、メモリーファイルをプロジェクトとして保存。仕事用と個人用の環境をワンクリックで切り替えられます。
アカウントと認証
再ログインが必要なアカウントやデフォルトアカウントを、ひとつの場所で管理します。

04利用状況

今月、何にどれだけ使ったか。

セッション数、トークン数、費用、キャッシュヒット、アクティブ時間をローカルに記録。日ごとの推移や、曜日 × 時間帯のヒートマップで、よく使う時間を確認できます。

  • アプリ、プロバイダー、モデル別に確認

    合計額だけでなく、どのツールやモデルに費用がかかったかを確認できます。

  • リクエストごとに確認

    各リクエストのモデル、所要時間、トークン数、費用を記録。数字が合わないときも、詳細をたどれます。

  • 長いセッションも、状況を把握

    コンテキスト使用量のグラフと自動圧縮のしきい値を見ながら、新しいセッションに移るタイミングを判断できます。

05ローカルデータ

データの保存先を、わかりやすく。

PHI は開発元のクラウドバックエンドを持ちません。設定、セッション統計、利用記録はローカルの ~/.phi/ に保存し、サブスクリプションの OAuth トークンはシステムのキーチェーンで管理します。ローカル設定や保存済み統計の閲覧に PHI のクラウドサービスは不要です。オンラインモデルを使う際は、CLI またはローカルゲートウェイから選択したプロバイダーへ接続します。

いつものツールと、一緒に。

Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build の設定を PHI で管理できます。OpenCode、OpenClaw、Hermes、Pi、MiniMax Code は共存方式で接続し、元の設定ファイルは変更しません。

06はじめに

使い慣れたツールから、始めよう。

最初からすべて設定する必要はありません。まずひとつのツールを接続して、少しずつ自分の作業環境を整えていきましょう。

  1. 1

    PHI と使いたい CLI をインストール

    PHI はツールの管理と起動を担当します。CLI は各ツールの公式手順でインストールしてください。すでに入っていれば、そのまま使えます。

  2. 2

    プロバイダーと接続方法を設定

    自分のモデルサービス情報を入力し、「ルーティング」ページでプロバイダーへの直接接続かゲートウェイのルートグループを選びます。

  3. 3

    プロジェクトを開いて、作業開始

    macOS 13 以降では、アプリページの「＋」からディレクトリを選んで CLI を起動できます。他のプラットフォームでは外部ターミナルを使います。

よくある質問

ダウンロードの前に。

モデルや無料利用枠は付いていますか？

PHI はオープンソースのデスクトップツールで、モデルの利用枠は提供しません。プロバイダーの API キー、または使うツールが対応するサブスクリプションアカウントを用意してください。モデルの利用料は選択したサービスから請求されます。

Windows や Linux でもアプリ内で CLI を実行できますか？

内蔵ターミナルは現在 macOS 13 以降のみ対応しています。Windows と Linux では、PHI で設定管理、モデル接続、利用状況の確認を行い、CLI は外部ターミナルで実行してください。

キーやリクエストはどこに送られますか？

主な設定と利用データはパソコン内に保存し、サブスクリプションの OAuth トークンはシステムのキーチェーンに保存します。モデルへのリクエスト内容と必要な認証情報は、設定したプロバイダーに送信されます。信頼できるサービスに接続し、ローカルデータも適切に管理してください。

すべてのツールで、すべてのモデルや機能を使えますか？

ツール、モデル、プロバイダーによって異なります。ゲートウェイは対応するプロトコルを変換できますが、ツール呼び出しやコンテキスト長などの機能には違いがあります。接続後は、小さなタスクで動作を確認することをおすすめします。

更新や不具合の報告はどうすればよいですか？

アプリ内の「更新を確認」、または GitHub Releases から新しいバージョンを入手できます。不具合は GitHub Issues へ、OS のバージョン、ツール名、再現手順を添えて報告してください。キーなどの秘密情報は必ず伏せてください。
