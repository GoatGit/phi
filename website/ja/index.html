PHI を作った理由

ツールが増えるほど、統一された入口が必要になる。

Claude Code、Codex、Gemini CLI を同時に使っているかもしれません。それぞれ違うプロトコルで話し、設定も別々です。プロバイダーを変えるたびに三、四か所を直し、ルートを変えるには前回どのファイルを触ったか思い出す必要があります。

PHI はそれらをローカルのコントロールプレーンにまとめます。プロトコルはゲートウェイで相互変換し、通信はルートグループで振り分け、セッション記録はひとつの一覧に集め、ターミナルも同じウィンドウに置きます。プロバイダーの設定は一度で済み、複数のツールで使えます。PHI アカウントは不要で、設定と統計はこのマシンに残ります。モデルの利用には、ご自身のアカウントまたは API キーを使います。

開発の出発点は CC Switch 。独立したフォークとして、Tauri 2、Rust、React で開発しています。

01ゲートウェイの統合

4つのプロトコルを、ひとつの入口へ。

Claude Code は Anthropic Messages、Codex は OpenAI Responses、Gemini CLI は Gemini ネイティブで話します。接続先のプロバイダーは別のプロトコルでもかまいません。PHI が間に入って判別し、そのまま通すか変換するので、ツールごとにプロバイダーへ接続し直す必要はありません。

ひとつの入口、多くのツール
Claude Code、Claude Desktop、Codex、Gemini CLI、OpenCode など 10 のアプリが、同じプロバイダー群と同じルートを共有します。

利用できる変換は、アプリの入口と上流プロトコルによって決まります。Gemini CLI は現在、Gemini ネイティブの上流のみを受け付けます。プロトコルをまたぐ接続では、まず簡単なタスクでツール呼び出しとストリーミングを確認してください。

02ルートの統合

直接つなぐか、グループに任せる。

各アプリは従来どおりひとつのプロバイダーに直接つなげます。複数のプロバイダーやモデルをルートグループに入れ、PHI に戦略で選ばせることもできます。メンバーは同じプロトコルやモデルである必要はなく、転送時にゲートウェイが変換します。

判断モデル
モデルが直近のユーザーメッセージを読み、設定済みのルールからひとつ選び、そのメンバーにリクエストを渡します。モデルが選べるのはルールだけで、プロバイダーの指定や認証情報の読み取りはできません。

  • セッション親和性

    有効にすると、同じ会話はできるだけ同じメンバーに留まり、文脈を往復させずに済みます。

  • フェイルオーバー

    条件に合うエラーでは次のルートを試します。失敗が続くメンバーは一時的に冷却し、回復後に戻ります。

  • タイムアウトと再試行

    ストリーミングの初回バイト、無通信時間、非ストリーミングの総時間に上限を設け、遅いルートがぶら下がり続けないようにします。

ルートグループは入れ子にでき、メンバーにはプロバイダー、モデル、別のグループを指定できます。直接接続モードは PHI ゲートウェイを通らず、アプリ本来の接続方法を保ちます。

03セッションと記憶の統合計画中

セッションは、ツールを変えても引っ越さない。

現在、PHI は複数のツールがこのマシンに残したセッション記録をひとつの一覧に集められます。プロジェクト別にまとめ、検索し、元の記録を開き、再開コマンドをコピーできます。次は、ツールをまたぐ文脈と長期記憶をつなぎます。このプロジェクトで話したことを、毎回ゼロから言い直さなくて済むように。

現在

  • 各ツールのセッションを、ひとつの一覧で

    PHI は Claude Code、Codex、Gemini CLI などがこのマシンに残した記録を読み、プロジェクト別または時系列でまとめます。

  • 探せて、戻れる

    タイトル、ディレクトリ、メッセージ、セッション ID を検索。元の記録を開き、再開コマンドをコピーして、そのときの作業ディレクトリに戻れます。

計画中

  • ツールをまたぐ継続セッション

    Claude Code で始めた作業を、文脈を手で移さずに Codex で続けられます。

  • プロジェクトに沿う長期記憶

    好み、決定、プロジェクトの事実を保存し、確認・編集・削除できるようにしたうえで、次のセッションに引き継ぎます。

この章は方向性であり、提供済みの機能ではありません。ツールをまたぐ文脈と長期記憶は計画中で、現在のセッション閲覧は各ツールがこのマシンに保存した記録を読むだけです。

04CLI ターミナルの統合

モデルを整えたら、あとはターミナルで使うだけ。

アプリページ右上の「＋」をクリックするか、または ⌘Tを押して、ディレクトリを選べば起動します。PHI は CLI がインストール済みか確認し、選んだディレクトリで起動します。Claude Code、Codex、Gemini CLI など 9 つのツールをこの方法で開けます。設定したプロバイダーとルートグループは、そのターミナルの CLI にも引き継がれます。 現在は macOS 13 以降のみ対応。CLI が見つからない場合は、インストール案内を表示します。

  • 設定もターミナルも、タブで切り替え

    同じアプリ内で行き来できます。プロバイダーを変更したら、別のウィンドウを開かずにコマンドを実行。

  • 見比べたいときは、画面を分割

    同じツールのセッションを並べて、一方でコードを編集し、もう一方で結果を確認。上下分割もできます。

  • いつもの配色で作業

    PHI のライト／ダークテーマに合わせることも、内蔵の配色から選ぶこともできます。アプリページを切り替えても設定はそのまま。

  • 別のページを見ていても、実行は継続

    別のページで利用状況や設定を確認しても、プロセスは止まりません。戻ったら、そのまま入力を続けられます。

  • CLI を終了しても、シェルはそのまま

    同じシェルに戻るので、作業ディレクトリも直前の出力も残っています。

05設定

設定は一度書けば、ゲートウェイ、ルート、ターミナルが同じ設定を読みます。

プロバイダー、MCP、Skills、プロンプトをひとつの場所で管理し、各ツールが対応する形で設定に反映します。ゲートウェイとルートグループは同じプロバイダー情報を読み、ターミナルで起動した CLI もその設定を引き継ぎます。

プロバイダーとキー
複数のプロバイダーとモデルをまとめて、クリックで切り替え。サブスクリプションのログイン認証情報はシステムのキーチェーンに保存します。
MCP と Skills
サーバーとスキルを一覧で管理。どのツールに導入したか、有効になっているかを確認できます。
プロンプト
よく使うプロンプトをライブラリに保存。必要なときにコピーしたり、プロジェクト設定に書き込んだりできます。
プロジェクトのスナップショット
プロバイダー、MCP、Skills、メモリーファイルをプロジェクトとして保存。仕事用と個人用の環境をワンクリックで切り替えられます。
アカウントと認証
再ログインが必要なアカウントやデフォルトアカウントを、ひとつの場所で管理します。

06利用状況

今月、何にどれだけ使ったか。

リクエストはローカルゲートウェイを通り、セッション数、トークン、費用、キャッシュヒット、稼働時間がローカルの台帳に記録されます。日ごとの推移や、曜日 × 時間のヒートマップで、よく使う時間帯を確認できます。

  • アプリ、プロバイダー、モデル別に確認

    合計額だけでなく、どのツールやモデルに費用がかかったかを確認できます。

  • リクエストごとに確認

    各リクエストのモデル、所要時間、トークン、費用を記録します。どのルートが選ばれたかも判断トレースで確認できます。

  • 長いセッションも、状況を把握

    コンテキスト使用量のグラフと自動圧縮のしきい値を見ながら、新しいセッションに移るタイミングを判断できます。

07ローカルデータ

データの保存先を、わかりやすく。

PHI は開発元のクラウドバックエンドを持ちません。設定、セッション統計、利用記録はローカルの ~/.phi/ に保存し、サブスクリプションの OAuth トークンはシステムのキーチェーンで管理します。ローカル設定や保存済み統計の閲覧に PHI のクラウドサービスは不要です。オンラインモデルを使う際は、CLI またはローカルゲートウェイから選択したプロバイダーへ接続します。

いつものツールと、一緒に。

Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build の設定は PHI で管理できます。OpenCode、OpenClaw、Hermes、Pi、MiniMax Code は既存の設定ファイルを変えずに併用できます。この 10 アプリはすべて統一ルートに参加し、それぞれのプロトコルでローカルゲートウェイに接続できます。

08はじめに

使い慣れたツールから、始めよう。

最初からすべて設定する必要はありません。まずひとつのツールを接続して、少しずつ自分の作業環境を整えていきましょう。

  1. 1

    PHI と使いたい CLI をインストール

    PHI はツールの管理と起動を担当します。CLI は各ツールの公式手順でインストールしてください。すでに入っていれば、そのまま使えます。

  2. 2

    プロバイダーと接続方法を設定

    モデルサービスを入力し、「ルート」ページで直接接続かルートグループかを選びます。必要ならグループの戦略も選びます。

  3. 3

    プロジェクトを開いて、作業開始

    macOS 13 以降では、アプリページの「＋」からディレクトリを選んで CLI を起動できます。他のプラットフォームでは外部ターミナルを使います。

よくある質問

ダウンロードの前に。

モデルや無料利用枠は付いていますか？

PHI はオープンソースのデスクトップツールで、モデルの利用枠は提供しません。プロバイダーの API キー、または使うツールが対応するサブスクリプションアカウントを用意してください。モデルの利用料は選択したサービスから請求されます。

直接接続とルートグループは何が違いますか？

直接接続では、アプリが従来どおりひとつのプロバイダーにつなぎ、PHI ゲートウェイを通りません。ルートグループは複数のプロバイダーやモデルをまとめ、順序・ラウンドロビン・低使用量優先などの戦略で PHI が選び、失敗時は次へ切り替えます。メンバーは別プロトコルでもよく、ゲートウェイが変換します。

キーやリクエストはどこに送られますか？

主な設定と使用量データはこのマシンに保存し、サブスクリプションの OAuth トークンはシステムキーチェーンに預けます。ローカルゲートウェイ経由では、リクエストはまず PHI に届き、設定したプロバイダーへ転送されます。直接接続ではアプリがプロバイダーに直接つなぎます。どちらも、リクエスト内容と必要な認証情報は選んだプロバイダーに渡ります。

セッション統合と長期記憶は今使えますか？

セッション閲覧は利用できます。複数のツールがこのマシンに残したセッション記録をひとつの一覧に集め、プロジェクト別または時系列で表示し、検索し、再開コマンドをコピーできます。ツールをまたぐ継続セッションと長期記憶はまだ計画中で、利用できる版はありません。

Windows や Linux でもアプリ内で CLI を実行できますか？

内蔵ターミナルは現在 macOS 13 以降のみ対応しています。Windows と Linux では、PHI で設定管理、モデル接続、利用状況の確認を行い、CLI は外部ターミナルで実行してください。

更新や不具合の報告はどうすればよいですか？

アプリ内の「更新を確認」、または GitHub Releases から新しいバージョンを入手できます。不具合は GitHub Issues へ、OS のバージョン、ツール名、再現手順を添えて報告してください。キーなどの秘密情報は必ず伏せてください。
