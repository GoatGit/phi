为什么会有 PHI

工具越多，越需要一个统一的入口。

你可能同时在用 Claude Code、Codex 和 Gemini CLI。它们各自说不同的协议，各自记一份配置； 换一家供应商，就要在三四个地方各改一遍。想换条线路，还得先想起上次改的是哪个文件。

PHI 把这些收进一个本地控制平面：协议在网关里互转，线路按路由组分配， 会话记录先归到一个列表，终端就在同一个窗口。供应商填一次，几个工具一起用。 不需要注册 PHI 账号，配置和统计留在本机；模型服务仍使用你自己的账号或 API Key。

它从 CC Switch 独立开发而来，用 Tauri 2、Rust 和 React 写成。

02统一路由

直连，或者交给一个组。

每个应用都可以直接连一个供应商，保持原来的连接方式；也可以把几家供应商、几个模型放进路由组， 让 PHI 按策略挑选。组内成员不必同协议、同模型，网关会在转发时完成转换。

决策模型
先让一个模型读最近一条用户消息，在已配置的规则里选一条，再交给对应成员。模型只能选规则，不能指定供应商或读取密钥。

  • 会话粘性

    开启后，同一段对话尽量落在同一个成员上，上下文不用来回搬。

  • 故障转移

    符合条件的错误会触发下一条线路；持续失败的成员暂时冷却，恢复后再接。

  • 超时与重试

    流式首字节、流式静默、非流式总时长分别设上限，慢线路不会一直挂着。

路由组可以嵌套，成员可以是供应商、模型，也可以是另一个组。直连模式不经过 PHI 网关，保持应用原来的连接方式。

03统一会话与记忆规划中

会话不该跟着工具换地方。

现在，PHI 已经能把多个工具留在本机的会话记录收进一个列表：按项目分组、搜索、打开原文， 或复制恢复命令。接下来，把跨工具的上下文和长期记忆也接起来—— 你在这个项目里说过的事，不必每次从头再说。

现在

  • 一个列表，翻遍各工具的会话

    PHI 读取 Claude Code、Codex、Gemini CLI 等工具留在本机的记录，按项目或时间归在一起。

  • 搜得到，也回得去

    搜索标题、目录、消息或会话 ID；打开原文，复制恢复命令，回到当时的工作目录。

规划中

  • 跨工具的连续会话

    在 Claude Code 里开的头，换到 Codex 也能接着做，不用手工搬上下文。

  • 跟着项目的长期记忆

    把偏好、决定和项目事实存下来，由你查看、修改和删除，再带进下一次会话。

这一章是方向，不是已交付的功能。跨工具上下文与长期记忆仍在规划中；现有会话浏览只读取各工具自己保存在本机的记录。

04统一 CLI 终端

模型配好了，就在终端里用。

应用页右上角的「＋」，或者按一下 ⌘T，选个目录就能启动。 PHI 会检查本机的 CLI 是否已安装，找到后在所选目录启动。 Claude Code、Codex、Gemini CLI 等 9 种工具，都可以这样打开。 配置好的供应商和路由组，会跟着终端里的 CLI 一起生效。 目前仅 macOS 13+ 可用；未安装的 CLI 会显示安装提示。

  • 配置和终端，各占一格标签

    同一个应用里来回切，改完供应商不用另开窗口去跑命令。

  • 需要对照，就左右分屏

    同一工具的两个会话并排放：一边改代码，一边检查结果。也可以上下分屏。

  • 配色跟着你走

    跟随 PHI 的浅色／深色，或从几套内置配色里挑一个，换应用也不会丢。

  • 切走了，它还在跑

    去别的页面看用量、改配置，进程不会被打断；回来接着输入就好。

  • CLI 退出，也不黑屏

    回到同一个 shell，工作目录和刚才的输出都还留着。

05配置

配置写一遍，网关、路由和终端一起认。

供应商、MCP、Skills 和提示词放在一处管理，再按工具支持的方式应用到配置中。 网关和路由组读同一份供应商资料，终端里的 CLI 也直接继承这套配置。

供应商与密钥
多家供应商、多个模型放在一起，切换只要点一下。订阅类登录凭据交给系统钥匙串保管。
MCP 与 Skills
统一的服务器与技能列表，装到哪些工具、有没有生效，一眼能对上。
提示词
常用提示词存成一份库，随时复制，或直接写进项目配置。
项目快照
把当前供应商、MCP、Skills 和记忆文件存成一个项目，工作和个人环境一键切换。
授权中心
哪个账号需要重新登录、哪些是默认账号，集中在一处处理。

06用量

这个月花在哪，心里有数。

请求经过本地网关，会话数、Token、费用、缓存命中和活跃时长都会记进本地账本。 按天看趋势，或者用星期 × 小时的热力图，看看自己通常什么时候用得最多。

  • 按应用、供应商、模型拆开看

    知道钱花在哪个工具、哪个模型上，而不是只有一个总数。

  • 请求能点开

    每条请求的模型、耗时、Token 与费用都有记录；路由选了哪条线路，也能在决策跟踪里对上。

  • 长会话有底

    上下文水位曲线和自动压缩阈值，提醒你什么时候该开新会话。

07本地

数据在哪，说得清楚。

PHI 没有项目方的云端后端。配置、会话统计和用量账本都在本机 ~/.phi/ 里，订阅类 OAuth Token 交给系统钥匙串。 查看本地配置和已有统计不依赖 PHI 云端服务。使用在线模型时，CLI 或本地网关会连接你选择的供应商。

08开始使用

从你熟悉的工具开始。

不用一次配好所有东西。先连通一个工具，再慢慢整理自己的工作台。

  1. 1

    装好 PHI 和你要用的 CLI

    PHI 管理和启动工具，CLI 仍需按其官方说明安装；已有的安装可以继续用。

  2. 2

    添加供应商，选好连接方式

    填好模型服务，在「路由」页决定直连还是加入路由组；需要时给组选一个策略。

  3. 3

    打开项目，开始做事

    macOS 13+ 可在应用页点「＋」选目录启动 CLI；其他平台继续使用外部终端。

你可能想问

下载前，再说清几件事。

PHI 自带模型或免费额度吗？

PHI 是开源桌面工具，不提供模型额度。你需要自行准备模型供应商的 API Key 或对应工具支持的订阅账号；模型费用由所选服务商收取。

直连和路由组有什么区别？

直连让应用按原来的方式连接一个供应商，不经过 PHI 网关；路由组把多个供应商或模型放在一起，由 PHI 按顺序、轮询、低用量优先等策略挑选，失败时换下一条。组内成员可以是不同协议，网关会转换。

我的密钥和请求会经过哪里？

主要配置与用量数据保存在本机，订阅类 OAuth Token 存入系统钥匙串。走本地网关时，请求先到 PHI，再转给你配置的供应商；直连时由应用直接连接供应商。两种方式下，请求内容和必要凭据都会交给你选择的供应商。

会话和长期记忆现在能用吗？

会话浏览已经可用：PHI 能把多个工具留在本机的会话记录收进一个列表，按项目或时间查看、搜索并复制恢复命令。跨工具的连续会话和长期记忆仍在规划中，还没有可以使用的版本。

Windows 和 Linux 也能在应用内运行 CLI 吗？

内嵌终端目前仅适用于 macOS 13 及以上。Windows 和 Linux 可以使用 PHI 管理配置、连接模型和查看用量，CLI 在外部终端运行。

如何更新和反馈问题？

在应用内选择「检查更新」，或到 GitHub Releases 获取新版本。遇到问题可以在 GitHub Issues 反馈，附上系统版本、工具名称和复现步骤，记得隐去密钥。
