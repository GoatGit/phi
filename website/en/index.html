Why PHI exists

The more tools you use, the more you need one entry point.

You probably use Claude Code, Codex and Gemini CLI at the same time. Each speaks a different protocol and keeps its own configuration; switching providers means editing three or four places. Changing a route means remembering which file you edited last time.

PHI brings them into one local control plane: protocols are translated in the gateway, traffic is assigned by route groups, session records meet in one list, and the terminal sits in the same window. Set up a provider once and use it across tools. There is no PHI account; configuration and stats stay on your machine, and model access still uses your own accounts or API keys.

An independent fork of CC Switch, built with Tauri 2, Rust and React.

Four wire protocols
OpenAI Chat Completions, OpenAI Responses, Anthropic Messages and native Gemini. Pick one for the entry point and one for the upstream; they don't have to match.
Same-protocol passthrough
When both sides speak the same protocol, requests pass through as they are; streaming, tool calls and usage fields are not rewritten.
Cross-protocol translation
Requests, responses and streaming events are translated to the target protocol; tool calls, reasoning content and token usage are preserved wherever possible.
One entry point, many tools
Claude Code, Claude Desktop, Codex, Gemini CLI, OpenCode and five more — ten apps share one set of providers and routes.

Available conversions depend on the app's entry point and the upstream protocol. Gemini CLI currently accepts only a native Gemini upstream; after a cross-protocol setup, try a simple task first to confirm tool calls and streaming.

02Unified routing

Direct, or hand it to a group.

Each app can connect straight to one provider and keep its original connection. Or put several providers and models into a route group and let PHI pick by strategy. Members don't have to share a protocol or model; the gateway translates as it forwards.

Decision model
A model reads the latest user message, picks one of your configured rules, and hands the request to that rule's member. The model can only choose a rule; it cannot name a provider or read credentials.

  • Session affinity

    When enabled, a conversation stays with the same member as much as possible, so context doesn't move back and forth.

  • Failover

    Matching errors trigger the next route; a member that keeps failing cools down and returns when it recovers.

  • Timeouts and retries

    Set limits for streaming first byte, streaming idle time and total non-streaming time, so a slow route can't hang forever.

Route groups can nest: a member can be a provider, a model or another group. Direct mode bypasses the PHI gateway and keeps the app's original connection.

03Unified sessions and memoryIn planning

Sessions shouldn't move when you switch tools.

Today PHI already gathers session records several tools keep on this machine into one list: group by project, search, open the source, or copy a resume command. Next, cross-tool context and long-term memory connect too — what you said in a project shouldn't have to be repeated from scratch.

Now

  • One list for every tool's sessions

    PHI reads the records Claude Code, Codex, Gemini CLI and other tools keep on this machine, then groups them by project or time.

  • Find it, then get back to it

    Search titles, directories, messages or session IDs; open the source, copy a resume command, and return to the working directory you used.

In planning

  • Continuous sessions across tools

    Start in Claude Code, continue in Codex without moving the context by hand.

  • Long-term memory that follows the project

    Keep preferences, decisions and project facts where you can review, edit or delete them, then carry them into the next session.

This chapter is a direction, not a shipped feature. Cross-tool context and long-term memory are still in planning; today's session browser only reads the records each tool keeps on this machine.

04Unified CLI terminal

Models are ready. Use them in the terminal.

Click “+” at the top right of an app page, or press ⌘T, pick a folder and go. PHI checks whether the CLI is installed, then starts it in the folder you chose. Nine tools, including Claude Code, Codex and Gemini CLI, open this way. The providers and route groups you configured carry into the CLI in that terminal. Currently available on macOS 13+ only. If a CLI is missing, PHI shows installation guidance.

  • Settings and terminals, in tabs

    Switch between them in the same app. Change a provider, then run a command without opening another window.

  • Put sessions side by side

    Open two sessions of the same tool side by side: edit in one, check results in the other. Vertical splits work too.

  • Keep your preferred colors

    Follow PHI's light or dark theme, or pick a built-in palette. Your choice stays with you across app pages.

  • Leave the tab. Keep it running.

    Check usage or change settings on another page without interrupting the process. Come back and carry on typing.

  • A shell after your CLI exits

    Return to the same shell, with your working directory and previous output still there.

07Local data

Know where your data lives.

PHI has no project-operated cloud backend. Configuration, session statistics and usage records are stored locally in ~/.phi/. Subscription OAuth tokens use the system keychain. Viewing local settings and existing statistics does not require a PHI cloud service. Online model requests go from the CLI or local gateway to your chosen provider.

Works with the tools you already use.

PHI can manage configuration for Claude Code, Claude Desktop, Codex, Gemini CLI and Grok Build; OpenCode, OpenClaw, Hermes, Pi and MiniMax Code connect alongside it without touching their existing config files. All ten apps can join unified routing and reach the local gateway in their own protocol.

Common questions

A few things before you download.

Does PHI include models or free credits?

PHI is an open-source desktop tool and does not include model credits. Bring your own provider API key or a subscription account supported by your tool. Your chosen service provider charges for model usage.

What's the difference between direct and a route group?

Direct mode lets an app connect to one provider the way it always did, without going through the PHI gateway. A route group puts several providers or models together, and PHI picks by ordered, round robin, least used or another strategy, moving to the next on failure. Members can use different protocols; the gateway translates.

Where do my keys and requests go?

Main configuration and usage data stay on this machine; subscription OAuth tokens go to the system keychain. Through the local gateway, requests reach PHI first and are then forwarded to the provider you configured; in direct mode the app connects to the provider itself. Either way, request content and the credentials it needs go to the provider you chose.

Are unified sessions and long-term memory available now?

Session browsing is available now: PHI gathers session records several tools keep on this machine into one list, where you can view them by project or time, search them, and copy a resume command. Continuous sessions across tools and long-term memory are still in planning, with no usable release yet.

Can I run CLIs inside PHI on Windows or Linux?

The built-in terminal currently requires macOS 13 or later. On Windows and Linux, use PHI to manage settings, connect models and track usage, and run your CLIs in an external terminal.

How do I update or report a problem?

Choose “Check for updates” in the app, or visit GitHub Releases for the latest version. Report problems on GitHub Issues with your OS version, tool name and steps to reproduce. Remember to remove any keys.
